# 团队通信

这是 Scathiard、主策划与唯一长期执行者共享的追加式群组记录。当前由 Scathiard 手动提醒其他成员读取最新消息；自动通知以后按实际需要再做。

## 当前约定

- 只在文件末尾追加消息，不修改、删除、重排或静默修正历史。需要纠错时追加一条新消息，并引用原消息。
- 固定称呼为 `@Scathiard`、`@Planner`、`@Executor` 和 `@All`。`@All` 只要求全部阅读，不表示主策划与执行者同时修改同一产物。
- 消息 ID 使用发送者自己的序号：用户、主策划 `P-0001`、执行者 `E-0001`。追加前先回读文件末尾，避免重复编号。
- 可按需要使用 `ACK`、`CLAIM`、`ROUTE`、`QUESTION`、`ANSWER`、`DONE`、`BLOCKED` 和 `OBJECTION`；这些是便于协作的当前约定，不要求为了格式妨碍正常工作。
- 清晰的产品问题由主策划处理，清晰的纯工程问题由执行者处理。混合问题可拆成不同产物；对同一产物发生重复认领时，先说明分工再继续。
- 本文件负责传递和追溯消息。玩家行为与产品决定进入 `项目计划书.md` 或对应规格；实现、验证和实际进度进入 `开发状态.md` 或相应技术记录。
- 项目初始化 Git 后，本文件纳入版本历史。提交时应验证上一个已提交版本是当前文件的完整前缀；本地 Git 不等于异地备份。
