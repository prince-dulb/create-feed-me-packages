## 1. 重排结论

### 2026-09-06 参考轨实测迭代

Scathiard 要求 @Planner 继续跟进数轮版本，并批准把原 test.14／15 合并为 **test.14**：修复存取交接与复制风险、接入合成预留以纠正采购时机，并完成固定背包优先、链节编号和绑定光效。唯一佩戴、后台残包与面板操作改排下一轮 **test.15**。完整方案与实际证据见 [参考迭代方案](../../reference/v0.1.0/docs/ITERATION_PLAN.md)；这一授权不把根工程解冻，也不自动进入插件／退货实现。

用户已经确认：四种扩容链节编号 1—4、绑定光效、固定背包优先且无开关、最多佩戴一件、残包后台自动处理、格距与角点收敛、减少等级文字／长提示／大按钮；美术重做另议。产品正文已同步，以下功能路线按新规则解释。

新路线按风险依赖分为五条版本线：

| 版本       | 主题        | 核心结果                                             |
| -------- | --------- | ------------------------------------------------ |
| `v0.1.0` | 两类缓存与补货闭环 | 普通／私人定坠、1—5 级、序列升级、真实补货、收件口、合成／JEI／标准投射物、纸飞机与蜂联调 |
| `v0.2.0` | 真实退货      | 最高阈值、运输物格、返回地址、纸飞机与一次性蜂发运；不以前置插件为条件              |
| `v0.3.0` | 插件构筑      | 通用插件舱、首批真实插件、重复安装、原子拆装和容量安全；回归与既有退货的事务隔离         |
| `v0.4.x` | 生态兼容      | TaCZ、带插件背包访问、无 Curios 护甲入口、JEI/EMI 与其他已选适配       |
| `v1.0.0` | 稳定公开基线    | 完整文档、性能与多人稳定化，并在公开前明确正式存档兼容政策                    |

排序理由：

1. 本件缓存、个人缓存和包裹目标路由是所有后续功能的数据基础，必须先稳定。
2. 插件会改变容量与功能，但不引入远端物资转移；先做插件，能先证明降容拒绝与私人化合并。
3. 退货同时涉及真实扣库、包裹生成和第三方载具生命周期，放在缓存与插件事务稳定之后。
4. TaCZ、第三方背包和无 Curios 入口各有独立 API 与版本风险，不阻塞核心玩法。
5. 项目尚未发布；`v1.0.0` 以前不为旧 `test.N` 设计兼容模块。正式存档兼容政策留到首次公开基线前单独确定，不在当前预发布阶段虚构承诺。

R0 的作用是把新模型变成执行者可以忠实实现的规格。R0 不生成新 JAR，也不延续旧代码。

- 重写规格 01—04，使缓存归属、终端、多缓存、补货、收件口和界面没有旧玩家单缓存残留；

**退出证据**

- 全仓搜索不再把材料名当等级、不再把所有缓存写成玩家附件、不再把简易升级配方写成现行方案；

- @Planner 在团队通信里发出可实施摘要。

**退出证据**

## 4. `v0.1.0`：核心供给闭环

### 4.1 版本目标

玩家可以制造、绑定并佩戴普通供应链坠，使用本件缓存完成真实补货；也可以把普通坠子全量私人化，获得随玩家的私人定坠。两种缓存都能保存精确物品、升级至 5 级、接收满背包包裹，并为原版合成、JEI 和标准投射物提供真实现货。

### 4.2 包含范围

- Curios 项链槽中的供应链坠与供应链坠·私人定坠；
- 潜行右击任一可解析网络物件绑定、原生方式清绑、绑定光效和唯一佩戴限制；异常多件不能暗选缓存；
- 服务端生成并显示专用投递地址，提供复制按钮；
- 本件缓存、个人缓存、全状态私人化、已有个人缓存全量原子合并；私人定坠物主锁定（锻造者），非物主佩戴退化为普通坠；
- 精确 `ItemVariantKey`、完整组件保真、重复过滤拒绝和合法堆叠取存；
- 1—5 级固定格数／容量／插件槽权益；
- 正式 Create 序列组装升级，不使用旧简易升级件；
- Create 风格左侧物流面板、局部双端滑条、实际库存箭头和按格手动重置；
- Create 真实缺口请求、请求承诺、防重复发单、连续标准分包；
- 带缓存目标的服务收件口、一个真实残包槽、部分入库和残包续收；
- 原版2×2／3×3、配方书及JEI recipe transfer；JEI ghost拖拽设过滤暂时停用，配方查看保留；
- 固定背包优先，背包不足时缓存补足；
- 标准投射物共享消费链，至少覆盖弓、弩与一个非 ID 特判测试物；
- 纸飞机与运输蜂分别完成真实补货闭环；
- 当前 schema 的首次创建、保存重载、多人隔离与坏数据安全拒绝。

### 4.3 不包含范围

- 可安装插件、插件舱 UI 或占位插件物品；
- 最高阈值触发的真实退货与上箭头；
- TaCZ；
- 无 Curios 的供应链甲／供应链盔；
- 第三方背包访问插件；
- EMI 与所有模组工作台；
- 旧 `test.N` schema、注册 ID 或测试世界迁移；
- Git push、平台上传或公开发布。

1—5级在本版本已经确定未来插件槽权益，但玩家看不到空白插件面板；`v0.2.0`先完成退货，`v0.3.0`再用真实插件内容开放插件舱。

### 4.4 实施里程碑

#### R1：缓存内核与两类终端

**工作**

- 实现 `CacheHandle`、世界本件缓存注册表、玩家个人引用和统一事务接口；
- 实现普通／私人定坠、网络绑定与清绑、唯一佩戴门；第二件提前拒绝，异常强制多件安全停用，卸下多余件恢复；
- 实现精确物品格、等级、请求／收据／残包字段；
- 实现普通缓存私人化、既有个人缓存模拟与原子合并；物主在锻造时写入 `OWNER`；
- 实现物主锁定（非物主佩戴退化为普通坠）与物主直接升级（无需授权认领）。

**完成证据**

- 普通坠转交后完整访问同一缓存；私人定坠只由物主自身佩戴访问物主的个人缓存，转交给他人时不转移缓存访问；
- 未绑定佩戴仍可访问缓存和处理目标明确的迟到包，但不能发新请求；清绑或换网不清现货、请求记录或残包；
- 死亡、掉落、卸下、换维度、断线和重启不产生第二份库存；
- 最后合法入口毁坏与异常副本测试符合 G-04；
- 合并成功逐字段守恒；任一容量、槽数、插件预留或残包冲突时整体不动；
- 伪造玩家 ID、`cacheId`、旧菜单或修订号均被服务端拒绝。

#### R2：面板、格子与等级

**工作**

- 重做生存／创造共用的左侧面板；
- 重建独立创造模式标签页、投递地址显示与复制入口；
- 实现精确物品拖入、取存、清除过滤和重复检查；
- 实现格内角点、局部双端滑条、下箭头、按格重置和滚动，不再提供终端管理或残包取回按钮；
- 实现 1—5 级序列组装与数据提交；
- 只保存插件槽权益，不显示未开放插件 UI。

**完成证据**

- 五级数值严格为 9／128／1、16／256／2、24／512／3、30／1,024／4、36／2,048／5；
- 物品图标不遮状态箭头或小点，移动中的物品不会被面板吞掉；
- 生存／创造都能打开同一功能面板，已开放物品可从独立创造标签页取得，地址复制结果与服务端显示一致；
- 小于等于一组与大于一组的取出都进入合法光标／背包位置，不掉到世界；
- 有库存不能清过滤；取空后可清；持物右键只存1个，左键按容量存入；JEI ghost停用时无拖拽目标、不改过滤／库存，配方查看和填充仍正常；
- 1 级末行单格、高级滚动、GUI 缩放、配方书与 JEI 开关组合都有截图与操作记录；
- 配方预览和自动化模拟不升级缓存、不变更物主或所有权。

#### R3：请求、路由与收件口

**工作**

- 实现按实际库存和有效请求记录计算缺口；
- 接入真实 Create 请求入口与精确组件库存／出包；
- 给请求和包裹绑定目标缓存令牌；
- 实现服务收件口、收据、部分入库、残包续收和按格重置；
- 对地面拾取、手动取得与后备扫描建立幂等入口。

**完成证据**

- 网络库存为 0、部分、足量和结果未知时的请求量与箭头正确；
- 玩家手动补足后箭头消失但请求账本保留，再次消耗不重复采购；
- 同一包重复发现十次只结算一次；
- 满背包时完整可收包不占普通格；部分包只减少实际入库量；
- 残包槽被占用时不接管第二个无法拆空的包；
- 手拆／移走残包后不保留幽灵状态；
- 目标令牌无法验证时不猜缓存、不动原包。

#### R4：合成、JEI 与投射物

**工作**

- 抽象“查询候选／预留／真实提交”的缓存消费服务；
- 接入原版 2×2、3×3、配方书与 JEI；
- 接入标准投射物查询／消费协议；
- 实现固定背包优先和背包／缓存混合补足；合成按已确认的可撤销预留／真实提交规则实施，准备不扣料或触发补货。

**完成证据**

- 查询、预览、取消拉弓和失败操作零扣料；
- 成功合成、箭矢消费和弩装填只扣一次；
- 弩发射不二次扣箭；无限、创造、多重射击保留原规则；
- 批量合成、组件原料、桶等余物和无输出空间均守恒；
- 一个未登记物品 ID、但遵循标准协议的测试武器可使用缓存弹药；
- 未佩戴或中途卸下时不能借旧客户端操作继续消费缓存。

#### R5：双运输与稳定化

**工作**

- 分别按原生规则联调纸飞机和运输蜂；
- 验证单装、共存、缺失、满背包、跨维度、区块加载和成员限制；
- 跑多人、保存切点、坏包、性能与可选依赖隔离矩阵；
- 按已确认的后台残包方向验证自动处理，不再保留手动取回按钮；隐藏表现不能掩盖真实余货。

**完成证据**

- 两种载具都从真实 Create 网络把完整包送入正确缓存；
- 两者共存时一个缺口只提交一次 Create 请求；
- 卸载任一或全部运输模组时核心仍加载，已经取得的合法包仍能处理；
- FMP 不冒充蜂成员、不改写原生目标、不把预拆散装物当完整包；
- 满背包四条入口的观察与最窄适配均有具体版本记录；
- 没有 P0／P1 物资守恒、越权或路由缺陷。

#### R6：本地版本交付

**工作**

- 跑当前项目定义的完整自动测试、GameTest、客户端、专服与人工矩阵；
- 更新中英文资源、依赖清单、变更说明和分层验证记录；
- 依次保留 `release/v0.1.0-test.N/`，达到全部完成门后生成 `release/v0.1.0/`。

**完成证据**

最终目录包含唯一可安装 JAR、依赖说明、变更说明、已知限制和验证记录。生成本地目录不代表允许 push、打标签或上传平台。

### 4.5 `v0.1.0` 总验收

除 R1—R6 的证据外，必须通过：

1. 普通缓存、本件转交、个人缓存、私人化和物主锁定（非物主退化、物主连续升级）的身份测试；
2. 精确组件从背包到缓存、包裹、合成／弹药再返回世界的完整往返；
3. 重复请求、手动重置、迟到包、部分包和保存切点的物资守恒；
4. 未佩戴、第二件佩戴拒绝、异常多件安全拒绝、卸下后恢复与伪造操作；
5. 生存／创造、不同 GUI 缩放、配方书／JEI 共存；
6. 纸飞机、蜂、单装、共存、缺失与满背包真实闭环；
7. 当前干净 schema 的跨 JVM 保存重载与坏数据拒绝；
8. 没有任何旧测试迁移器、别名注册或双格式解码路径。

## 5. `v0.2.0`：真实退货

### 5.1 进入条件

- `v0.1.0`补货、包裹路由、私人化与容量事务稳定；不要求插件已实现；
- 关闭**G-RETURN-01**，分别验证纸飞机与蜂的真实发运入口；
- 明确返回地址表示、发运前检查、满站、目标丢失、保存重载和失败落包行为。

### 5.2 包含范围

- 最高数量启用、超额计算、红／灰上箭头；
- 专用运输物格和返回地址设置，不占用尚未开放的插件舱；
- Create标准连续分包；
- 发运成功后才从缓存扣除交接货物；
- 纸飞机真实退货；
- 格内原蜂不消耗、派出一次性临时蜂；
- 临时蜂状态持久化、成功交付销毁、失去目标终止销毁与原包当地掉落；
- 原生重选站行为与实际串网观察。

### 5.3 不包含范围

- 通用插件舱与首批插件，仍仅保留等级已有的槽位权益；
- 新增退货站、FMP全局寻路、自动赔付；
- 未经实际观察就专门重写运输蜂防串网逻辑。

### 5.4 验收

- 恰好等于最高值不退货，超过时只发超额部分；
- 不能出发时不打包、不扣缓存、不消耗运输物格；
- 模拟、启动失败、保存重载、目标丢失与重复回调均不复制或吞物；
- 一次性蜂不能通过任何回收路径变成普通蜂；
- 纸飞机与蜂分别有真实发运、交付、失败与满站记录；
- 不安装任何FMP插件即可完成退货；同一物资不能同时被合成预留和退货占用。

## 6. `v0.3.0`：插件构筑

### 6.1 进入条件

- `v0.1.0`缓存、私人化、容量事务与`v0.2.0`退货稳定；
- Scathiard关闭**G-PLUGIN-01**：确认首批插件名单、效果、重复公式、硬上限、互斥关系与配方；
- 每个会降低有效容量或改变消费规则的插件都有独立失败策略。

### 6.2 包含范围

- 一个玩家可见的通用插件舱；
- 1—5级分别开放1—5个通用槽，任意合法插件进入任意槽；
- 重复实体逐件占槽；同功能按存在性生效，数值件逐个进入固定公式；
- 插件随当前缓存保存与转交；
- 安装、拆卸、换位、互斥和容量降低的服务端模拟／原子提交；
- 私人化合并中的插件多重集、槽数、冲突和容量复核；
- 首批插件的Create制造流程与完整UI反馈。

### 6.3 不包含范围

- 插件增加插件槽、跳级或替代永久等级；
- 未经决定的“死亡不掉落”“容量提高”等示例自动转成首批内容；
- 为了插件读取而提前开放所有第三方背包；
- 新增退货载具或改变0.2已定的基本发运规则。

### 6.4 验收

- 任意重复组合保存重载后实体数量、顺序和效果一致；
- 两个同功能插件只执行一次，移除一个但仍剩一个时效果不断；
- 数值公式与硬上限在安装顺序变化后结果一致；
- 互斥、槽满、降容超限和私人化冲突均在提交前拒绝，所有物资保持原位；
- 不得为让拆卸或私人化通过而自动发退货腾位；真实退货、收件和合成预留与插件事务互不重复占料；
- 插件舱关闭或对应模组缺失时核心缓存数据仍可安全读取；
- 5级加合法目标插件构筑能达到该方向定义的最大能力。
