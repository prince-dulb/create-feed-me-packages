- 旧总计划与路线图分别保存为[plan-v1.0 总计划快照](../项目计划书-plan-v1.0-历史.md)和[旧路线图快照](版本路线图-plan-v1.0-历史.md)，只用于追溯。

- 本轮只修改文档；未修改源码、构建配置、schema、注册 ID、存档或 release，未运行 Gradle、GameTest、客户端、专服或第三方联调。

## 1—5 级、插件槽与预发布无兼容合同 — 2026-09-05

- 玩家可见的结构成长正式改为 1—5 级；旧“石／铁／安山／黄铜／坚固板”仅是被替代的讨论说法，不再作为等级名或强制材料顺序。
- 1—5 级依次为 9／128／1、16／256／2、24／512／3、30／1,024／4、36／2,048／5（物流格／单格容量／通用插件槽）。每级只新增一个空插件槽，不生成插件。
- 等级永久成长与插件可逆构筑是两套增强；5 级与针对目标的合法插件组合才达到该目标最高能力。插件不能改写等级、增加槽位或跳过序列扩容。
- 项目尚未发布首个正式版本，`test.N` schema、材料等级名与旧升级件注册 ID 不构成兼容合同。新模型不提供兼容别名、双格式解码或旧测试存档迁移模块；旧测试世界允许失效，但代理不得删除用户存档。
- 2026-09-04 schema 1→2 的代码与测试仍是已经执行的历史证据，精确组件 `ItemVariantKey` 产品语义继续有效；其迁移合同不再是重构后首个正式版本的交付要求。
- 受影响的路线图、架构、规格和测试任务继续暂停，等待本件／个人缓存与干净 schema 整体重写及实施授权。本次变更只修改文档。

## 精确组件身份与 schema 2 迁移 — 2026-09-04

- 用户确认缓存身份从裸 `itemId`／默认模板改为**物品注册 ID＋完整持久化数据组件**的精确变体；堆叠数量不属于身份。一个玩家内同一精确变体只设一格，同 ID 的不同弹种、气量或其他组件状态可分别占格。
- 可安全编码的带组件实物一次即可建立过滤并转入，不再剥离组件、不再弹出“改成默认模板”的二次确认。JEI ghost 保存精确 subtype 但不生成物资；无法完整往返、禁止作为普通材料或规范模板超过 1,024 B 时整体拒绝，来源不变。
- 所有业务路径统一使用不可变 `ItemVariantKey`：存取、Create 查询／请求、待收、收据、残包、事务日志、合成候选与弹药消费必须按完整组件精确相等并原样输出。散列只用于日志或快速比较，不能作为权威身份。
- 用户同时明确授权玩家缓存 schema 1→2 迁移。解码器接受 schema 1／2；旧过滤、待收和日志的裸 ID 键迁移为迁移时注册表中的默认精确变体，并保留数量、槽位、阈值、启用、修订、阶段、偏好、请求与事务字段；下一次成功保存写 schema 2。未知物品、非法模板或字段无法无损迁移时整条记录诊断封锁，不跳过、不清空、不覆盖。
- T02／T03／T05—T07／T10—T12 的受影响路径重新打开，实施顺序固定为协议→数据与迁移→UI／ghost→物流→合成→弹药→系统门。旧 `test.9` 的 72/72 JUnit 与 61/61 GameTest 保留为旧模型基线，不再证明这些任务按当前规格完成。
- T12 另有独立违规：当前实现在 `LivingGetProjectileEvent` 纯查询时扣缓存，测试也以查询扣料为成功；现规格要求查询和取消零扣、弓成功释放单扣、弩成功装填单扣且发射不重扣。完成声明与最终交付门保持暂停，直到真实提交点和测试矩阵通过。
- TaCZ 仍在后续版本。精确组件缓存只解决身份保真前提，不能代替锁定兼容版本、确认弹种数据和验证枪械真实消费入口。
- 本轮只修改产品、架构、规格、任务、路线图、状态与通信文档；未修改源码、构建、玩家文件或发布物，也未运行 Gradle／GameTest。

## 补货运输职责收缩与 T08／T09 改为联调 — 2026-09-03

- 依据用户在团队通信中的最新澄清：不涉及退货时，两种运输模组各自派送，FMP 不需要接管运输。
- 首版边界固定为 Create 真实请求与本地专用完整包接收；取消旧计划中的 `DeliveryProviderAdapter` 必交要求、目标登记／撤销、定位器替代和蜂成员检查。不以未安装运输模组或运输条件未知阻止 Create 请求，不猜测相应 UI 诊断。
- T08／T09 和 M4 改为原生运输联调，仍分别测试纸飞机与运输蜂、共存和完整包交接；先整理用户已有实测，只补缺项。测试通过不以新增适配器为前提，用户一次实测也不自动代表全矩阵通过。
- 同步 AGENTS、产品入口、架构、规格 02—04、任务、路线图、UI 状态及 C0／C1 测试条件；未安装运输附属时仍可请求真实 Create 包裹，自行取得的匹配包按本地规则入库。
- 架构中的请求流程图同时按原有规格 04 校准为“先持久化请求承诺，再调用 Create 派发”，不改变既定请求事务规则。
- P-0007 和首轮技术审查中要求“只佩戴供应链坠取代原生定位器”的后续方向撤回；不再为此建设兼容层。直接截包派飞也不属于首版。
- 退货仍为 `v0.2.0`；从玩家处使用纸飞机零件／运输蜂发运届时再做，已确认的一次性蜂规则不变。JEI、合成和标准投射物取料计划不变。
- 本次只修订规划与审查文档；没有修改源码、构建、存档或冻结交付，没有运行新的游戏测试。执行者随后同步工程状态与实际证据。

## T12 改为共享投射物消费协议 — 2026-09-02

- 用户明确否决按原版弓、弩物品 ID 分别特判；目标是在普通背包弹药耗尽后无缝使用缓存弹药，并让走同一标准消费操作的其他物品自动受益。
- 本地锁定版本核查确认共享查询入口为 `LivingEntity#getProjectile`／`LivingGetProjectileEvent`，共享消费链位于 `ProjectileWeaponItem.draw/useAmmo`。
- T12 改为统一耗材消费服务加投射物适配器；原版弓弩只是提交语义和回归样本，另须用未登记 ID 的非原版 `ProjectileWeaponItem` 测试子类证明协议级兼容。
- 不采用全局 `ItemStack.shrink/split/consume` 劫持；该层没有消费者、需求谓词、取消结果和提交时机，自写消费链的第三方物品须用独立适配器接入统一服务。

- 锁定 `v0.1.0` 的 Java 21、Minecraft 1.21.1、NeoForge 21.1.219、Create 6.0.10、Curios `9.5.1+1.21.1`、JEI `19.21.0.247`、纸飞机 2.3.0、运输蜂 `1.21.1-0.7.7` 基线。
- 锁定 `mod_id=create_feed_me_packages`、Maven group `dev.scathiard`、Java 包 `dev.scathiard.feedmepackages`、版本 `0.1.0` 和 MIT 代码许可证。
- 建立版本路线图、架构、六份功能规格、非功能需求、测试策略、T00—T15 任务拆分和本索引。
- 把个人缓存唯一权威固定为 NeoForge 玩家 Data Attachment；供应链坠只保存终端 ID、网络绑定、禁用状态和修订号。
- 把“有效佩戴”拆成两个门：本地访问不要求绑定网络，新请求额外要求单一饰品网络绑定、Create 网络可用和当前玩家合格的完整包提供者；Create 绑定随饰品转交，个人附件数据及蜂成员资格不随之转交。
- 固定待收每物品 4 条／每玩家 144 条、活动包裹事务日志 256 条且最多 256 KiB、20 tick 后备扫描和 100 tick 缺货重检上限。
- 固定 C0—C5 启动／兼容矩阵、40 组 UI 矩阵、两玩家专服、双运输真实闭环和故障注入门。

### 收口

- `v0.1.0` 包含供应链坠、个人缓存、五阶段、补货、本地部分拆包、纸飞机与运输蜂、原版／JEI 合成、弓弩。
- 退货固定进入 `v0.2.0`；TaCZ、护甲入口、背包插件和 EMI 进入 `v0.3.x`；正式序列组装进入 `v1.0.0`。
- Create 请求成功值只记为可手动重置的本地请求承诺，不描述为载具状态或已送达。
- 包裹到达即按第一次观察到的实际内容扣减待收；缓存装不下的实物继续留在原包，手拆或移走后不保留假残包状态。
- Create 查询与请求只接受服务端默认组件身份；无法把默认实例与同 ID 特殊变体精确区分时阻塞该物品发单。
- 收包采用整包预验证、一次性收据和单条整包事务日志；畸形包、收据不匹配、日志满载和四个保存切点均以不改实物或严格守恒为门槛。
- 完全未佩戴时界面消失；仍佩戴但全部禁用时保留可重新启用／清绑的管理入口，避免配置死锁。
- T05 只负责核心面板与 JEI 布局共存，T11 独占 JEI ghost 与 recipe transfer 的实现和验收。

## 变更流程

1. 产品规则改变：先更新项目计划书并注明用户依据，再更新路线图、规格、测试和任务。
2. 技术验证改变实现方案：先记录 Spike 证据和失败处理，再更新架构与受影响规格；不得借技术失败静默删需求。
3. 依赖、工程标识、存档格式或许可证改变：同时更新技术栈核查、路线图、AGENTS、兼容矩阵和本记录。
4. 只修正错字或断链且不改变语义时，可直接修正，不提升计划版本；在交付说明中汇总即可。
