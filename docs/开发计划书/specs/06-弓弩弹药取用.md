# 投射物弹药取用规格

- **版本**：0.1.0，里程碑 M5
- **优先级**：`[A] / P0`
- **前置依赖**：[个人缓存](01-个人缓存与持久化.md)、[供应链坠](02-供应链坠与网络绑定.md)、来源优先级开关
- **范围**：所有沿用 Minecraft `LivingEntity#getProjectile` 与 `ProjectileWeaponItem` 标准查询／消费链的玩家物品；原版弓弩是首轮验收样本
- **规格状态**：消费语义、“不按弓弩物品 ID 特判”和精确组件弹药已固定；`test.9` 在纯查询入口扣料，已确认不符合本规格，T12 重新打开

## 用户故事

> 作为玩家，我希望使用会从背包查询并消费弹药的投射武器时，在普通背包弹药耗尽后无缝使用缓存现货，并遵守背包优先／缓存优先设置。

> 作为服务器管理员，我希望拉弓查询、取消蓄力、弩装填中断、无限和多重射击都保持原版计费，缓存只在真实成功操作中扣一次。

## 范围与明确排除

本规格包含：

- `LivingEntity#getProjectile(ItemStack)`／NeoForge `LivingGetProjectileEvent` 的共享弹药查询入口。
- `ProjectileWeaponItem` 标准消费链中的缓存来源和真实提交；不检查消费者是否恰好是原版 `BowItem` 或 `CrossbowItem`。
- 原版 `BowItem` 释放和 `CrossbowItem` 装填作为两种不同提交时机的必测实现。
- 第三方 `ProjectileWeaponItem` 子类若沿用上述标准查询与消费链，应无需逐物品注册即可获得缓存弹药；必须用一个非原版测试子类证明，不能只从继承关系推断兼容。
- 普通箭、光灵箭、药箭、烟花火箭等由原版武器判定为合法的投射物；缓存可提供自身真实保存的任意安全精确组件变体。
- 手中明确弹药、普通物品栏和缓存之间的确定性优先级。
- 无限、创造、多重射击、取消、装填和发射只扣一次。

本规格不包含 TaCZ、发射器、工具耐久、食物或药水。第三方枪械、Create 土豆炮及其他物品若绕开标准投射物链、自行扫描背包并直接 `shrink/split/consume`，不能被本规格自动接管；它们通过同一缓存消费服务的独立适配器接入。全局劫持所有 `ItemStack` 数量变化不属于方案，因为该层缺少消费者、需求谓词、取消结果和提交时机，无法保证物资守恒。

## 原则

1. 本模组只补充弹药来源，不改武器蓄力、精度、伤害、弹道、附魔、耐久或声音。
2. 兼容查询可以返回“缓存有候选”，但查询本身不能扣缓存。
3. 弓在实际射击提交时扣；弩在实际装填提交时扣，发射已装填弩不再扣。
4. 原版判定消费为 0 时缓存也扣 0；不能先扣再返还。
5. 缓存候选必须是现货、完整 `ItemVariantKey` 可安全还原、且原版武器接受该精确栈。待收与远端库存不能当弹药。
6. 未佩戴、全部禁用或异网冲突时，原版背包弹药行为继续正常；只是缓存不参与。
7. 适配单位是“查询／消费协议”，不是物品注册表 ID。走同一标准协议的新物品默认继承支持；自写协议的物品必须显式适配，不能因最终也调用了 `ItemStack.shrink` 就宣称兼容。

## 共享消费服务

T12 建立内部 `AuxiliaryItemConsumptionService`，投射物只是首个适配器。服务接收服务端构造的消费者栈、候选谓词、所需数量、来源优先级、查询／提交阶段与操作 ID，统一完成普通背包和缓存的候选选择、重检、扣减、防重及补货置脏。

`ProjectileAmmoAdapter` 负责把标准投射物调用翻译为该服务的输入。后续若另一类物品具有可靠的“查询需求 → 操作最终提交 → 扣除真实来源”入口，可以新增适配器复用服务，不复制一套弓／弩专用缓存逻辑。适配器不得只在全局 `ItemStack.shrink/split/consume` 上猜测调用上下文。

## 来源选择

### 手中明确弹药

玩家非武器手中持有、且原版判定合法的投射物始终保持原版最高优先级。这是玩家直接用手作出的明确选择，不受背包／缓存开关覆盖。

### 自动来源

手中没有合法弹药时：

| 设置与访问状态 | 搜索顺序 |
| --- | --- |
| `localAccess` 不活动或冲突 | 只执行原版普通物品栏搜索 |
| 背包优先 | 原版普通物品栏／快捷栏稳定顺序 → 缓存格索引升序 |
| 缓存优先 | 缓存格索引升序 → 原版普通物品栏／快捷栏稳定顺序 |

先按原版武器谓词排除不合法投射物，再按上述来源顺序选第一个真实候选；选中后保留该候选的确切物品与组件，不能把它转换成另一弹种。除手中明确弹药始终优先外，切换背包／缓存优先可能有意改变两个自动来源中最终选中的合法弹种，这正是开关的作用。

缓存按精确组件变体储存。带药水数据的药箭、定制烟花和第三方组件弹药只要通过缓存模板安全校验，就可作为独立候选；选择、装填与投射物生成全程保留组件。本模块不得去除组件，也不得把同 ID 变体合并。

## 逻辑计划

### `ProjectileUsePlan`

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `weaponSlot` | 受控槽定位 | 服务端实际武器 |
| `consumer` | `ItemStack`／受控手槽 | 实际发起弹药需求的物品；不限制为弓或弩 ID |
| `commitProfile` | 适配器定义 | 释放时消费、装填时消费或其他标准链可验证提交点 |
| `sourceKind` | `HAND / INVENTORY / CACHE / VANILLA_FREE` | 候选来源 |
| `sourceSlot` | 可选受控槽／缓存格号 | 不能由客户端指定 |
| `projectile` | `ItemStack` 数量 1 | 从真实来源或缓存 `ItemVariantKey` 生成的完整组件防御性副本 |
| `consumeCount` | `0 / 1` | 由原版模式和附魔规则计算 |
| `expectedCacheRevision` | `long?` | 缓存来源才有 |
| `operationId` | `UUID` | 一次释放或装填提交的服务端 ID |

该计划仅在一次服务端武器调用内存活，不持久化，不发送给客户端。查询阶段返回只读候选，不创建 `operationId`。

## 原版弓验收流程

### 查询阶段

原版检查“是否有弹药可以开始使用”时：

1. 先让原版查手中和普通物品栏。
2. 若访问有效，再按来源优先级把缓存中的精确变体作为只读候选。
3. 返回用于允许开始蓄力的视图；不减少任何栈，不改缓存修订号，不触发补货。

反复右击、客户端预测和仅拉开未释放都停在这一阶段。

### 提交阶段

服务端弓释放流程已经确定会发射、所有可取消事件也已允许后：

1. 重新执行来源选择，不信任查询阶段对象。
2. 由原版规则计算 `consumeCount`。创造模式或无限附魔对所选投射物判定不消耗时为 0。
3. 普通物品栏来源继续由原版减少；缓存来源在同一调用中验证格号、物品、现货和修订号。
4. `consumeCount=1` 时缓存减少 1；`consumeCount=0` 时缓存不变，但把真实组件副本交给原版构造投射物。
5. 原版生成投射物、播放声音、损耗武器。缓存减少后格子加入补货脏集合。

如果提交瞬间缓存候选已不存在，重新尝试下一合法来源；全部来源均无弹药时按原版无弹药结果结束，不生成投射物、不扣缓存。

## 原版弩验收流程

### 查询与蓄力

开始使用、持续蓄力和中断使用只查询候选，不扣弹药。Quick Charge 等只影响原版装填时长。

### 成功装填

在原版即将把投射物写入弩的 `CHARGED_PROJECTILES` 数据且装填没有取消时：

1. 重新选择真实来源。
2. 原版多重射击仍只消费 1 份来源，并按原版构造多个已装填投射物副本。
3. 缓存来源在装填组件成功写入的同一服务端调用中扣 1；写入失败或操作取消扣 0。
4. 缓存减少后触发补货评估。

### 发射

弩发射已经保存在武器组件中的投射物。本模组不再查询或扣普通物品栏／缓存；原版清除装填状态并发射。

## 事务与事件顺序

缓存来源必须满足以下顺序：

```text
原版确认操作可提交
  → 所有取消钩子已通过
  → 服务端重选真实来源
  → 模拟武器组件／投射物写入
  → 在同一主线程调用内扣缓存并提交原版操作
  → 缓存 revision + 1
  → 触发补货脏标记
```

若目标 1.21.1 方法不能在缓存扣减和原版提交之间形成无失败区，Mixin 必须把两者包在一个可回滚的局部事务中；不得在 `LivingGetProjectileEvent` 等纯查询入口扣料。

同一 `operationId` 在该调用内只能提交一次。服务端玩家动作天然串行；任何兼容回调重复进入时，第二次看到已提交 ID 直接返回原结果。

## 原版规则保留

| 原版情形 | 缓存行为 |
| --- | --- |
| 弓蓄力不足，不产生箭 | 扣 0 |
| 弓取消／事件取消 | 扣 0 |
| 创造模式免费弹药 | 扣 0，按原版生成投射物 |
| 无限附魔适用于所选箭 | 扣 0；不把不适用弹种变免费 |
| 无限附魔不适用所选弹药 | 按原版扣 1 |
| 弩装填中断 | 扣 0 |
| 弩成功装填普通箭 | 扣 1 |
| 弩多重射击 | 按原版扣 1，不按三支扣 3 |
| 弩发射已装填弹药 | 扣 0 |
| 烟花弩 | 使用缓存中真实存在且武器接受的完整烟花组件变体 |
| 武器耐久不足或损坏 | 保持原版结果，不以缓存补偿 |

## 输入与输出

本功能由服务端武器生命周期触发，没有专用“消耗弹药”C2S payload。客户端只执行原版使用物品包；服务端从实际手、武器、附件和物品栏构造计划。

缓存变化沿用统一 S2C 增量快照，包含格号、新数量、新修订和补货状态。客户端投射物渲染继续使用原版实体同步。

## 错误与降级

| 状态 | 玩家行为 | 缓存行为 |
| --- | --- | --- |
| `CACHE_ACCESS_INACTIVE` | 原版可用弹药仍能射／装填 | 不参与 |
| `NETWORK_CONFLICT` | 原版可用弹药仍能射／装填，并提示缓存停用 | 不参与 |
| `NO_VALID_PROJECTILE` | 按原版无弹药 | 不变 |
| `CACHE_PROJECTILE_CHANGED` | 重选普通背包或其他缓存候选 | 旧格不扣 |
| `CACHE_REVISION_CHANGED` | 在同一服务器调用重新求解一次 | 不能重复扣 |
| `OPERATION_CANCELLED` | 不发射／不装填 | 不变 |
| `UNSUPPORTED_CONSUMPTION_PATH` | 物品绕开标准投射物链且没有独立适配器 | 保持该物品原行为，不猜测扣料 |

本模组的异常不能阻断普通背包原本可以完成的射击；缓存增强失败后必须回到原版来源或原版无弹药结果。

## 边界条件

- 缓存有箭、普通背包无箭：有效佩戴时可射；未佩戴时按原版无箭。
- 背包与缓存都有箭：按开关选源，手中箭仍优先。
- 选中缓存候选后，同 tick 另一操作取空该格：提交阶段重选，不产生负数。
- 缓存有待收但现货 0：不能开始依赖缓存的蓄力或装填。
- 弓使用无限：只有原版对当前弹种判定免费时缓存扣 0。
- 弩多重射击：缓存有 1 即可按原版装填，成功后缓存减 1。
- 弩已经装填后卸下供应链坠：仍可发射武器内真实投射物，不再访问缓存。
- 拉弓过程中卸下：释放时重检；普通背包无箭则不使用缓存。
- 缓存优先但缓存中的首个合法物品是普通箭、背包手持特殊箭：手持特殊箭优先，保留玩家明确选择。
- 服务器安装修改投射物事件的模组：所有取消与消费规则必须在 Spike 记录；只有实际走完共享查询与提交链的子类才算自动兼容。

## 技术 Spike

### `SPK-AMMO-01`：原版 1.21.1 弓弩提交点

记录 `LivingEntity#getProjectile`、NeoForge `LivingGetProjectileEvent`、`ProjectileWeaponItem.draw/useAmmo`，以及 `BowItem` 释放、`CrossbowItem` 装填和 `CHARGED_PROJECTILES` 写入的完整服务端调用图。选择满足“取消钩子之后、不可失败提交之前”的最窄 hook。查询和候选选择必须位于共享入口；不同提交语义允许使用不同适配器提交点，但都调用同一消费服务，不按物品 ID 分支。

通过标准：下列矩阵中查询／取消扣 0，弓成功射击与弩成功装填按原版只扣一次，普通背包原有路径没有行为变化；另建一个非原版 `ProjectileWeaponItem` 测试子类，不为其登记物品特例，仍能从缓存选择并消费合法弹药。测试必须经过真实释放／装填提交路径，不能直接调用 `getProjectile` 后以扣料作为成功。

### `SPK-AMMO-02`：原版投射物矩阵

测试普通箭、光灵箭、药箭默认／带药水组件、烟花默认／定制组件、无限、创造、多重射击、快速装填和耐久边界。输出“缓存可存且武器接受”的实际集合；集合由通用谓词计算，不在代码硬编码物品清单。

## Given / When / Then 验收

1. **Given** 背包无箭、缓存有 1 支普通箭，**When** 有效佩戴并完整释放弓，**Then** 生成原版箭、缓存减 1、触发补货。
2. **Given** 同样库存，**When** 拉弓后取消，**Then** 缓存仍为 1，无投射物。
3. **Given** 查询事件被调用 20 次，**When** 从未实际释放，**Then** 缓存修订号和数量均不变。
4. **Given** 手中有合法特殊箭、缓存优先且缓存有普通箭，**When** 发射，**Then** 使用手中箭，缓存不扣。
5. **Given** 背包与缓存都有箭，**When** 分别切换两个优先级发射，**Then** 每次只从排在前且真实可用的来源扣 1。
6. **Given** 弓的无限附魔对当前箭适用，**When** 使用缓存候选发射，**Then** 投射物正常、缓存扣 0；不适用时扣 1。
7. **Given** 弩装填中断，**When** 未写入装填组件，**Then** 缓存扣 0。
8. **Given** 弩成功从缓存装填，**When** 随后发射，**Then** 装填时扣 1、发射时不再扣。
9. **Given** 多重射击弩和缓存 1 支箭，**When** 成功装填并发射，**Then** 按原版产生多投射物但缓存只减 1。
10. **Given** 弩装填后卸下坠子，**When** 发射，**Then** 已装填投射物照常发射，缓存不访问。
11. **Given** 蓄力过程中卸下坠子且背包无箭，**When** 释放，**Then** 不从缓存扣、不凭空射击。
12. **Given** 缓存有两个同 ID、组件不同且均被武器接受的弹药变体，**When** 按格序选择并成功提交，**Then** 只扣选中变体，投射物／装填组件与其完整组件相同，另一格不变。
13. **Given** 异网冲突但普通背包有箭，**When** 发射，**Then** 原版射击正常，只是不使用缓存。
14. **Given** 同一提交 hook 重入，**When** `operationId` 相同，**Then** 缓存最多扣一次。
15. **Given** 手中没有弹药、普通背包有光灵箭、缓存有普通箭，**When** 分别用背包优先和缓存优先射击，**Then** 各自选择对应来源的真实弹种且只扣该来源，不把已选弹种转换成另一种。
16. **Given** 一个非原版 `ProjectileWeaponItem` 测试子类沿用标准查询与 `draw/useAmmo`，且代码中没有该物品 ID，**When** 背包弹药耗尽而缓存有合法弹药，**Then** 无缝使用缓存并只扣一次。
17. **Given** 一个测试物品绕开标准链并自行减少任意背包栈，且没有注册适配器，**When** 使用该物品，**Then** 本模组不拦截、不误扣缓存，也不宣称支持。
18. **Given** 查询事件被其他模组或原版流程重复调用且候选是带组件弹药，**When** 玩家最终取消，**Then** 两个变体的数量和缓存修订均不变；只有最终提交选中的完整变体才扣一次。

## 验证状态

`test.9` 已有共享查询事件实现和 5 项 GameTest，但当前 `ProjectileAmmoService` 在 `LivingGetProjectileEvent` 中直接扣缓存，相关测试也把查询扣料写成通过条件；它们违反第 2—4 条原则及验收 2、3、7、8，不能作为 T12 完成证据。执行者须重新锁定弓释放与弩成功装填提交点，补齐真实流程及精确组件测试后再恢复完成状态。TaCZ 仍不在 0.1.0 验收范围。
