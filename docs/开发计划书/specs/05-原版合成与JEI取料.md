# 原版合成与 JEI 取料规格

- **版本**：0.1.0，里程碑 M5
- **优先级**：`[A] / P0`
- **前置依赖**：[个人缓存](01-个人缓存与持久化.md)、[供应链坠](02-供应链坠与网络绑定.md)
- **兼容测试基线**：JEI `19.51.0.418`；不是加载器依赖，每轮兼容验收前重新核实适用的 1.21.1 最新版
- **范围**：原版背包 2×2、原版工作台 3×3、原版配方书、JEI 对这两类菜单的配方转移
- **规格状态**：事务语义固定；具体 hook 由 `SPK-CRAFT-01` 和 `SPK-JEI-02` 固定

## 用户故事

> 作为玩家，我希望在原版配方书或 JEI 选择配方时，系统把缓存中的真实原料直接放进真实合成格，并按我的来源优先级与背包材料混用。

> 作为服务器管理员，我希望配方预览、失败转移、批量填充和界面关闭都保持物资守恒，不让客户端指定结果或凭空使用在途库存。

## 范围与明确排除

本规格包含：

- 配方选择后的原料可用量计算、候选选择、网格清理、来源分配和原子转移。
- 普通点击一份填充和入口原生支持的最大填充。
- 背包优先／缓存优先及首选不足时另一来源补足。
- 真实材料进入网格后由原版负责结果、消耗、Shift 合成和配方余物。

本规格不包含：

- 手工摆好任意网格后自动从缓存续栈。
- Create 机械合成、Crafter、其他模组工作台、机器配方、EMI 或所有 JEI recipe category。
- 直接从远端网络或待收数量合成。
- 自动把关闭界面后退回背包的材料塞回缓存。

## 核心原则

1. **先转移，后合成。** 缓存材料必须成为合成格中的合法真实 `ItemStack`，原版才能消费；本模组不直接生成结果。
2. **离开缓存即扣。** 材料成功进入合成格时缓存立即减少，并按新缓存数量触发补货。玩家之后取消并关闭界面时，原版把材料退回普通背包，缓存不会自动恢复。
3. **预览不扣。** 配方书可制作高亮、JEI 计算、客户端悬停、失败转移和仅查询最大次数都不改库存。
4. **只用本地现货。** 可用量等于普通玩家物品栏真实栈加缓存 `storedCount`；待收和 Create 远端库存为 0 可用量。
5. **原版决定结果。** 配方匹配、结果物、配方余物、解锁和功能开关仍由服务端原版配方与菜单决定。

## 输入

### `CraftTransferIntent`

| 字段 | 类型 | 来源与约束 |
| --- | --- | --- |
| `containerId` | `int` | 当前打开菜单；服务端必须与玩家菜单一致 |
| `recipeId` | `ResourceLocation` | 服务端 RecipeManager 重新解析 |
| `transferMode` | `SINGLE / MAX` | 配方书点击或 JEI 原生 transfer max 语义 |
| `viewerChoice` | 每个 ingredient 的可选 `ResourceLocation` | 只作为候选偏好；必须被服务端 Ingredient 接受且有真实来源 |
| `expectedCacheRevision` | `long` | 个人缓存乐观并发版本 |
| `requestNonce` | `UUID` | 当前菜单生命周期内去重；每次点击新建，不跨重开菜单复用 |

客户端不提交结果物、应消耗数量、来源槽列表、缓存数量或是否可制作。

服务端为每个打开的受支持菜单维护最多 32 条成功 nonce 与结果的有界表，关闭或替换菜单即清除。表满后淘汰最旧项仍安全，因为每次成功提交都会改变菜单状态及缓存修订，旧 payload 即使重放也会在状态复核处失败；nonce 不能替代槽与修订校验。

### 合法菜单

| 菜单 | 网格 | 菜单要求 |
| --- | --- | --- |
| 玩家背包合成 | 2×2 | 当前菜单为玩家 InventoryMenu，配方尺寸可放入 2×2 |
| 原版工作台 | 3×3 | 当前菜单为 CraftingMenu，玩家仍可使用该方块且菜单未失效 |

其他菜单收到意图返回 `UNSUPPORTED_MENU`。

## 输出

### `CraftTransferResult`

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `status` | `CraftTransferStatus` | 成功或稳定错误码 |
| `craftsPlaced` | `int` | 网格中实际放入的完整配方份数 |
| `cacheTaken` | `Map<ResourceLocation,long>` | 各缓存物品实际扣减 |
| `inventoryTaken` | `Map<ResourceLocation,int>` | 普通物品栏实际移动 |
| `returnedFromGrid` | `Map<ResourceLocation,int>` | 旧网格退回普通背包的数量 |
| `newCacheRevision` | `long` | 成功后的服务端版本 |
| `changedCacheSlots` | 快照列表 | 只含有变化的格 |
| `messageKey` | `String` | 本地化反馈 |

成功只表示网格真实填好，不表示玩家已经取走结果。

## 来源顺序

### 已在网格中的材料

当前网格中位置正确、物品及组件被目标 ingredient 接受的真实材料优先保留，不先退回再重复取。位置不正确、多余或不被目标接受的材料必须模拟退回玩家主物品栏；光标携带栈不参与自动清理和取料。

### 新材料

对仍缺的每一份材料：

| 玩家设置 | 顺序 |
| --- | --- |
| 背包优先 | 原版玩家主物品栏／快捷栏按原版稳定顺序 → 缓存格索引升序 |
| 缓存优先 | 缓存格索引升序 → 原版玩家主物品栏／快捷栏按原版稳定顺序 |

首选不足时必须用另一来源补足同一 ingredient。总量不足则整个转移失败，不留下半套网格变化。

## Ingredient 候选选择

每个 recipe ingredient 可能接受多个物品。选择顺序固定为：

1. 保留当前网格中已经匹配的物品。
2. 若 JEI／配方书提供的候选偏好被服务端 ingredient 接受且实际可用，使用该候选。
3. 其余候选按服务端物品注册 ID 字典序排列，选取能满足目标份数的第一项。
4. 单个候选不足时，不在同一个网格槽内混合两种不同物品；降低 `craftsPlaced` 后重新求解。

模板比较保留配方要求的组件。缓存可以提供已真实存储的精确组件变体，但只有服务端配方 ingredient 接受该完整栈时才算候选；同 ID 异组件不能合并计数，也不能为满足配方而清洗、补造或改写组件。

## 单份与最大填充

- `SINGLE` 目标为 1 份；现有网格已经有更多同配方材料时不主动删减，只补到至少可合成 1 次。
- `MAX` 先求可用原料支持的完整份数，再受每个目标网格槽的物品原生最大堆叠限制。结果最少为 1，否则失败。
- 有损坏工具、容器物品或配方定义的特殊次数语义时，以原版 placement／recipe API 的可放置数量为准，不用简单整数除法替代。
- 网格填好后，玩家 Shift 点击结果能连续合成的次数由原版当前网格真实材料决定；本模组不会在每次结果取出后暗中续填。

## 服务端事务

### 阶段 A：验证

1. 取得当前玩家、菜单和服务端配方。
2. 检查 `localAccess=ACTIVE`；未佩戴、全部禁用或异网冲突均拒绝。
3. 检查菜单、距离、配方尺寸、配方是否仍可用以及缓存修订号。
4. 同一 `requestNonce` 已成功处理则返回上次结果，不再次移动。

### 阶段 B：模拟

1. 复制网格、玩家主物品栏和相关缓存格的只读视图。
2. 用目标 recipe placement 计算 2×2／3×3 目标布局。
3. 模拟把不保留的旧网格材料退回普通背包；放不下即 `GRID_CLEAR_BLOCKED`。
4. 按来源顺序分配目标原料，求 `craftsPlaced`。
5. 模拟每个目标栈的合法组件与堆叠上限。
6. 任一份无法完整满足则不形成提交计划。

### 阶段 C：提交

1. 在同一服务端主线程调用中再次确认相关槽、网格和缓存修订未变。
2. 先把不保留的旧网格材料实际退回普通背包。
3. 按计划从普通物品栏移动材料，并从缓存扣减等量材料，直接写入真实网格。
4. 校验每种物品及总量守恒，缓存修订号加 1。
5. 通知原版菜单 slots changed，使服务端重新计算结果槽。
6. 把减少的缓存格加入补货脏集合；不等待补货完成。

若第 1 步发现状态变化，整个提交返回 `STALE_STATE`。模拟保证后，步骤 2—5 不调用可失败的外部物流或异步操作。

## 原版配方书入口

服务端拦截“在支持菜单中放置所选配方”的入口：

- `localAccess=ACTIVE` 时，即使原版仅用普通物品栏即可完成，也通过统一服务计算，以保持来源开关语义。
- 未佩戴、全部禁用或异网冲突时，本模组不接管配方放置，完全交还原版普通物品栏行为；冲突只停用缓存增强，不能让原版本来可填的配方失效。
- 配方书的可制作显示可以把缓存现货纳入客户端只读估算，但最终点击仍由服务端重算；待收不加入绿色可制作状态。
- 解锁限制、知识书和服务器配方禁用保持原版。

`SPK-CRAFT-01` 必须固定 1.21.1 的最窄 hook；若无稳定事件，使用仅覆盖原版配方放置方法的单点 Mixin，不替换整个菜单。

## JEI 入口

JEI 兼容模块注册 2×2 InventoryMenu 与 3×3 CraftingMenu 的 recipe transfer handler：

- handler 的模拟调用只返回缺料／空间／访问错误，不移动物资；
- JEI 确认 transfer 时发送 `CraftTransferIntent`，服务端执行同一服务；
- JEI 的 ghost ingredient handler 只负责物流格设过滤，不能复用为配方转移；
- JEI 未安装时该模块不加载，配方书功能不受影响；
- 不覆盖熔炉、机械动力机器或第三方菜单的 JEI transfer。

## 配方余物与关闭界面

本模组在网格填充阶段不预先生成桶、瓶等余物。玩家实际合成时由原版：

- 把余物留在网格、放入普通物品栏或按原版规则处理；
- 在结果无法取出时不消费下一次材料；
- 关闭工作台时把网格材料退回普通物品栏，放不下则按原版安全掉落。

从缓存来的材料已经在填格时扣除，因此这些后续材料不自动识别来源并返还缓存。玩家可手动存回，超过未来最高数量后再由退货版本处理。

## 错误状态

| 错误码 | 条件 | 结果 |
| --- | --- | --- |
| `ACCESS_INACTIVE` | 未佩戴／全部禁用 | 交还原版可用范围；不读缓存 |
| `NETWORK_CONFLICT` | 异网冲突 | 不使用缓存并交还原版普通物品栏放置；面板提示先解除冲突 |
| `UNSUPPORTED_MENU` | 非 2×2／3×3 原版菜单 | 不修改 |
| `RECIPE_NOT_FOUND` | 服务端没有该配方 | 不修改 |
| `RECIPE_TOO_LARGE` | 2×2 放不下 | 不修改 |
| `RECIPE_LOCKED` | 原版不允许玩家使用 | 不修改 |
| `GRID_CLEAR_BLOCKED` | 旧网格物品无处退回 | 网格、背包、缓存全不变 |
| `MISSING_INGREDIENTS` | 两来源合计不足 | 全不变，并返回缺少项 |
| `SPECIAL_COMPONENT_REQUIRED` | 背包与缓存均没有符合配方组件谓词的精确变体 | 不把同 ID 异组件伪装成合法原料，整次转移不变 |
| `STALE_CACHE_REVISION` | 缓存已变化 | 全不变，刷新快照 |
| `STALE_MENU` | 槽或菜单已变化 | 全不变 |
| `TRANSFER_ALREADY_COMMITTED` | 成功 nonce 重发 | 返回原结果，不二次移动 |

## 边界条件

- 普通背包 3、缓存 5、配方需 8：两种优先模式都成功，实际来源分配顺序不同，总量相同。
- 当前网格已有正确材料：只补缺，不把它先放回背包。
- 当前网格有无关物品且背包满：整体拒绝，不把无关物品掉地来强行填配方。
- 2×2 打开 3×3 配方：返回 `RECIPE_TOO_LARGE`。
- 操作提交后立即卸下坠子：已进入真实网格的物品保留；以后新的缓存取料停用。
- 意图到达前卸下坠子：不扣缓存。
- 配方候选包含同物不同组件：背包与缓存都按每个精确变体分别匹配 ingredient；只选择真实存在且完整组件被接受的变体。
- 结果槽已满或光标装不下不影响填格守恒；实际取结果继续服从原版。
- 玩家切换来源开关发生在模拟与提交之间：修订号变化使旧计划失败，不混用两套顺序。

## 技术 Spike

### `SPK-CRAFT-01`：原版配方放置入口

在 NeoForge 21.1.219 上记录 InventoryMenu／CraftingMenu 的客户端点击、服务端配方放置、普通／Shift 语义和 slots changed 顺序。输出唯一 hook、调用图和取消路径；通过标准是无需修改配方结果与消费代码。

### `SPK-JEI-02`：JEI recipe transfer

在届时适用的 Minecraft 1.21.1 NeoForge JEI 最新版（当前已用基线 `19.51.0.418`）上验证模拟与实际 transfer 的调用次数、`transferMax`、ingredient 选择和服务端菜单信息。输出隔离 handler；不得用客户端直接改格、把 JEI 设过滤当作 transfer，或把 JEI 重新写成加载器依赖。

### `SPK-CRAFT-02`：复杂配方与余物

最小矩阵包括有序、无序、标签候选、耐久／组件输入、蛋糕桶余物、修理类特殊配方、数据包配方和批量填充。无法由统一服务安全表达的特殊配方明确返回 `UNSUPPORTED_RECIPE_PLACEMENT`，不猜材料。

## Given / When / Then 验收

1. **Given** 背包 0、缓存有完整材料，**When** 配方书选择一份，**Then** 真实材料进入网格、缓存等量减少、结果由原版出现。
2. **Given** 背包 3、缓存 5、需 8，**When** 背包优先转移，**Then** 先用 3 再用缓存 5；缓存优先时顺序相反。
3. **Given** 两来源合计少 1，**When** 点击配方，**Then** 网格、背包、缓存完全不变。
4. **Given** 网格有无关材料且背包无空间，**When** 选择新配方，**Then** 返回 `GRID_CLEAR_BLOCKED`，无掉落和吞物。
5. **Given** 缓存材料填格成功，**When** 玩家关闭工作台未合成，**Then** 原版把它退入背包或安全掉落，缓存不自动增加。
6. **Given** 蛋糕配方使用缓存牛奶桶所代表的合法默认输入，**When** 实际合成，**Then** 桶余物按原版出现，总物资守恒。
7. **Given** `MAX` 模式可做 100 次但某格上限 64，**When** 填充，**Then** `craftsPlaced` 不超过网格合法堆叠限制。
8. **Given** 同一成功 nonce 发送两次，**When** 服务端处理，**Then** 只移动一次并返回同一结果。
9. **Given** 提交前卸下坠子，**When** 意图到达，**Then** 不扣缓存；提交后卸下不回滚真实网格。
10. **Given** JEI 未安装，**When** 客户端和专服启动，**Then** 配方书增强可用且不加载 JEI 类。
11. **Given** JEI 已安装，**When** 分别拖物品到物流格和点击配方 transfer，**Then** 前者只设过滤，后者移动真实材料，两条路径互不代替。
12. **Given** 待收有 64 但缓存现货 0，**When** 配方书计算与点击，**Then** 这 64 不算可用原料。
13. **Given** 配方要求组件变体 A 而缓存只有同 ID 变体 B，**When** 普通背包无 A，**Then** 明确缺料且全不变；缓存真实拥有 A 时可按原样填入合成格。
14. **Given** 结果槽无法继续取出，**When** 玩家 Shift 合成，**Then** 原版停止消费，本模组不额外扣缓存。
15. **Given** 玩家未佩戴或处于异网冲突且普通背包足够，**When** 使用原版配方书放置配方，**Then** 原版照常填格，缓存完全不参与；普通背包不足时也不借缓存补足。
