# 供应链坠与网络绑定规格

- **版本**：0.1.0，里程碑 M1
- **优先级**：`[A] / P0`
- **必需依赖**：Create 6.0.10、Curios 9.5.1+1.21.1
- **被依赖**：[个人缓存](01-个人缓存与持久化.md)、[物流格界面](03-物流格界面与五阶段.md)、[补货与收包](04-补货请求与本地收包.md)、合成与弓弩
- **规格状态**：产品行为固定；`SPK-TERM-01`、`SPK-TERM-02` 已在发布基线完成

## 用户故事

> 作为玩家，我希望每件供应链坠保存自己的一个网络绑定，但访问的始终是我自己的缓存，以便我可以为不同工厂准备不同坠子而不复制库存。

> 作为同时佩戴多件坠子的玩家，我希望同网多件表现成一件，异网多件明确停用并允许我当场禁用其中一件，以免系统偷偷选择错误工厂。

## 范围与明确排除

本规格包含供应链坠物品、Curios `necklace` 佩戴、网络绑定／清除、逐件禁用、佩戴归并、转交和服务端访问判定。

本规格不包含个人缓存的物资字段、无 Curios 护甲入口、供应链甲／供应链盔、退货运输格、饰品外观渲染和外部网络 ACL 的重写。

## 名称与资源标识

| 项目 | 值 |
| --- | --- |
| 中文名 | 供应链坠 |
| 英文名 | Supply Chain Pendant |
| 物品 ID | `create_feed_me_packages:supply_chain_pendant` |
| Curios 槽 | `necklace` |
| 物品标签 | `curios:necklace` |
| 玩家槽数据 | `data/create_feed_me_packages/curios/entities/player.json`，向玩家加入 `necklace` |

供应链坠最大堆叠为 1。它不增加属性，不改变死亡掉落规则；个人缓存不在物品内，因此饰品掉落或销毁不会删除缓存。

## 数据模型

每个供应链坠保存一个持久化、网络同步的数据组件：

| 字段 | 类型 | 默认值 | 约束 |
| --- | --- | --- | --- |
| `schemaVersion` | `int` | 1 | 只接受当前可读版本 |
| `terminalId` | `UUID` | 服务端首次创建 | 用于定位和诊断，不是缓存主键 |
| `networkId` | `UUID?` | `null` | 未绑定或一个 Create 物流网络；不存在列表 |
| `disabled` | `boolean` | `false` | 逐件开关；不清绑定 |
| `revision` | `long` | 0 | 本件每次成功配置变化加 1 |

组件不能包含玩家 UUID、缓存格、库存数量、阶段、来源偏好或待收记录。

## 佩戴枚举与归并

服务端从 Curios 实际物品栏枚举 `necklace` 及通用 `curio` 槽中所有供应链坠，按“槽类型 ID、槽索引、终端 ID”稳定排序。普通背包、快捷栏、掉落实体和其他玩家槽中的坠子不参与。

先忽略 `disabled=true` 的坠子，再构造非空 `networkId` 集合：

| 条件 | `localAccess` | `requestAccess` | 界面 |
| --- | --- | --- | --- |
| Curios 中没有供应链坠 | `INACTIVE` | `BLOCKED_NOT_WORN` | 不显示本系统 |
| 有佩戴坠子但已启用坠子 0 件 | `MANAGEMENT_ONLY` | `BLOCKED_DISABLED` | 只显示终端列表和启用按钮 |
| 已启用坠子至少 1 件，网络集合为空 | `ACTIVE` | `BLOCKED_UNBOUND` | 显示缓存和“未绑定”原因 |
| 网络集合恰好 1 个 | `ACTIVE` | 继续校验网络 | 显示缓存；同网多件只列一次有效网络 |
| 网络集合多于 1 个 | `MANAGEMENT_ONLY` | `BLOCKED_CONFLICT` | 只显示冲突列表和终端配置 |

未绑定坠子与一个已绑定网络共存时不构成第二个网络，`requestAccess` 使用那个非空网络。同网多件不增加格数、容量、请求频率或收包次数。

## 输入

客户端不能直接提交网络 UUID。所有改变由以下意图发起：

| 意图 | 输入 | 服务端事实来源 |
| --- | --- | --- |
| 标准物品方块交互（绑定） | 方块位置、手 | 当前手中栈、交互距离、目标方块实体实际挂载的 `LogisticallyLinkedBehaviour`；不枚举具体方块类，也不使用自定义客户端 UUID payload |
| `ClearBindingIntent` | Curios 槽定位、预期终端 ID／修订号 | 当前实际佩戴栈 |
| `SetTerminalDisabledIntent` | Curios 槽定位、预期终端 ID／修订号、目标布尔值 | 当前实际佩戴栈 |
| `OpenTerminalManagementIntent` | 当前菜单 ID | 当前 Curios 枚举 |
| `CopyDeliveryAddressIntent` | 无 | 服务端当前玩家名；只返回 `FMP@玩家名` |

绑定是一项标准方块交互：玩家手持供应链坠，对已加载且实际加入 Create 物流网络的任意网络组件潜行右击。服务端确认玩家可交互该方块后，通过 Create 的行为查询取得 `LogisticallyLinkedBehaviour`，从中读取 UUID，并把它写入手中这件坠子。不得用 Stock Link、Stock Ticker 等具体方块类白名单代替行为查询；相同 UUID 重绑返回成功但不增加修订号。

清除绑定与逐件启用／禁用必须在任一管理态仍可提交；否则玩家无法解除冲突或从全部禁用恢复。它们只作用于定位到的实际物品，不按物品 ID 批量修改。

| 字段 | 类型 | 含义 |
| --- | --- | --- |

## 交互流程

### 首次制作与绑定

1. 服务端创建供应链坠栈时生成 `terminalId`；若外部来源给出缺失组件的合法栈，首次服务端交互补齐组件。
2. 玩家手持该坠子潜行右击任意实际挂载 Create 物流链接行为的网络组件。
3. 服务端读取真实网络、写入组件并显示短网络 ID。
4. 玩家把它装备到 Curios `necklace`；本地访问立即启用，新请求再按 Create 网络、库存及受理状态判断。

### 清除绑定

1. 玩家在面板终端管理区点击“清除绑定”。
2. 服务端按槽定位和终端修订号找到同一件坠子。
3. `networkId` 设为 `null`，本件修订号加 1。
4. 重新归并全部坠子。个人缓存、待收和已发包裹均不变。

### 解除异网冲突

1. 冲突态不返回可操作缓存，只列出所有已启用已绑定坠子。
2. 玩家禁用其中一件；服务端只改该件 `disabled=true`。
3. 若剩余网络集合大小不再大于 1，立刻恢复本地访问；新请求仍需其他门通过。
4. 被禁用件保留网络，之后重新启用会再次参与冲突判断。

若玩家把最后一件已启用坠子也禁用，归并状态转为 `MANAGEMENT_ONLY / BLOCKED_DISABLED`，而不是隐藏全部入口。该管理态只接受按实际 Curios 槽定位的启用、清绑和只读终端列表操作；重新启用一件后按完整网络集合重新归并，可能恢复本地访问，也可能重新进入异网冲突。

## 网络资格

核心 Create 6.0.10 没有供本项目复用的通用玩家 ACL。核心层的可用资格由三个事实组成：

- 绑定发生时，玩家实际触碰并有权交互该物流网络组件；
- 绑定结果保存在供应链坠上；合法持有并佩戴该坠子即继承这项 Create 网络绑定能力；
- 发单时，存储的网络 UUID 仍有可见物流链接，且 Create 请求入口接受该网络。

2026-09-03 用户明确：补货运输沿用原模组。运输蜂的玩家成员资格由 Mobile Packages 自行检查；纸飞机目标由原生定位方式建立。供应链坠不代替定位器、不登记或撤销目标、不管理成员，也不据此拒绝 Create 补货请求。

因此，转交已绑定坠子会转交该坠子的 Create 网络绑定，但不会转交原持有者的个人缓存、格子、阶段、偏好或待收。知道 `FMP@玩家名` 或从客户端直接发送 UUID 不能创建绑定、选择他人缓存或绕过真实佩戴；也不能改变原运输模组的权限。捡到但没有合法佩戴不激活任何本模组能力。

## 生命周期

| 事件 | 终端数据 | 个人缓存 | 功能状态 |
| --- | --- | --- | --- |
| 卸下 | 留在物品 | 留在玩家附件 | 若无其他已启用坠子则停用 |
| 丢出／放容器 | 留在物品 | 留在玩家附件 | 不激活 |
| 转交 B | 绑定和禁用随物品到 B | A、B 各自数据不变 | B 可使用本件 Create 绑定；蜂成员等原生运输条件由原模组按 B 判断 |
| 死亡 | 按 Curios／游戏规则处理物品 | 玩家附件复制 | 重生后按实际佩戴重新判定 |
| 清除绑定 | 只清该件 UUID | 不变 | 本地仍可用，新请求可能未绑定 |
| Stock Link 被拆 | 物品仍保留 UUID | 不变 | 请求显示网络不可用，不自动清绑定 |
| 玩家改名 | 终端不变 | UUID 归属不变 | 收货地址使用当前名字；旧地址包不自动改写 |

## 错误状态

| 错误码 | 条件 | 状态变化 |
| --- | --- | --- |
| `NOT_A_TERMINAL` | 目标栈不是供应链坠 | 无 |
| `TERMINAL_MOVED` | 槽中终端 ID 与预期不符 | 无，返回新快照 |
| `STALE_TERMINAL_REVISION` | 本件修订号已变化 | 无，返回新快照 |
| `TARGET_NOT_STOCK_LINK` | 兼容保留的协议名；目标没有有效 Create 物流链接行为 | 无 |
| `TARGET_UNLOADED` | 方块或区块在提交时无效 | 无，不强制加载 |
| `OUT_OF_REACH` | 玩家不在合法交互距离 | 无 |
| `INTERACTION_DENIED` | 服务器保护或普通交互失败 | 无 |
| `NETWORK_DATA_UNAVAILABLE` | 无法从实际物流行为读取 UUID | 无，记录兼容错误 |
| `DUPLICATE_TERMINAL_ID_REPAIRED` 诊断 | 同一玩家装备复制 ID | 稳定排序后较后的栈获服务端新 ID、`revision + 1`，网络绑定与禁用值保留；快照返回本次修复数 |
| `NETWORK_CONFLICT` | 非管理操作发生于异网冲突 | 拒绝该操作 |

## 边界条件

- 一个已绑定、一个未绑定：不冲突，使用已绑定网络。
- 两个未绑定：本地访问有效，没有新请求网络。
- 两个同网：不冲突，只执行一次缓存与补货逻辑。
- A、B 两网，其中 A 禁用：不冲突，使用 B。
- 冲突时卸下其中一件：下一次服务端枚举立即解除，不要求重开游戏。
- 菜单打开后终端换槽、卸下、被替换：所有旧定位意图失败。
- 创造模式复制终端：个人缓存不会复制；同一玩家同时装备时修复重复终端 ID。
- 他人终端携带有效网络 UUID：B 只能访问 B 的缓存，但可用该 UUID 对应的 Create 网络发单；蜂路线还须 B 是该网络成员。

## Given / When / Then 验收

1. **Given** 新供应链坠，**When** 只放普通背包，**Then** 本系统不显示、不扫描、不允许缓存操作。
2. **Given** 未绑定坠子已装备，**When** 打开背包，**Then** 可存取个人缓存，补货显示未绑定且不广播。
3. **Given** 手持坠子合法潜行右击任意挂载 Create 物流链接行为的组件，**When** 服务端提交，**Then** 只给该栈写一个真实网络 UUID，客户端未提供 UUID，且实现没有具体方块白名单。
4. **Given** 两件分别绑定 A、B 且均启用，**When** 同时装备，**Then** 进入管理态，缓存、合成、弓弩、收包和新请求均不执行。
5. **Given** 上述冲突，**When** 禁用 A，**Then** 本地访问恢复且请求网络为 B；A 的绑定仍在。
6. **Given** 两件都绑定 A，**When** 同时装备并触发一个缺口，**Then** 容量不叠加，只广播一次。
7. **Given** 一件绑定 A、一件未绑定，**When** 同时装备，**Then** 不冲突且请求网络为 A。
8. **Given** A 把已绑定网络 N 的坠子交给 B，**When** B 装备，**Then** B 看到 B 的缓存；A 的现货、格子、阶段、偏好和待收均未转移，坠子仍显示绑定 N。
9. **Given** 网络 N 仍可用且 Create 有可请求库存，**When** B 的缓存产生缺口，**Then** 系统可用转交来的绑定向 N 提交请求，不要求 B 再次触碰 Stock Link，也不额外检查配送模组。
10. **Given** B 不具备运输蜂网络成员资格，**When** 尝试蜂路线，**Then** 原模组自行判断能否配送；FMP 不伪造成员、不虚构运输诊断，核心本地缓存及 Create 请求仍按自身条件可用。
11. **Given** 玩家清除当前唯一绑定，**When** 操作成功，**Then** 缓存、待收和世界旧包不变，新请求停在未绑定状态。
12. **Given** 菜单打开后坠子被卸下，**When** 旧菜单提交存取，**Then** 服务端返回 `ACCESS_INACTIVE`，不改物资。
13. **Given** 两个复制的相同终端 ID 同时装备，**When** 服务端枚举，**Then** 稳定排序后较后的栈得到新 ID 且修订加 1，网络配置保留且个人缓存仍只有一份。
14. **Given** 玩家佩戴的所有供应链坠都被禁用，**When** 打开背包，**Then** 不显示缓存格但显示最小终端管理入口；重新启用一件后按其实际绑定恢复或进入冲突，不要求重新合成坠子。
