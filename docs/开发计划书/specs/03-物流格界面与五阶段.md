# 物流格界面与五阶段规格

- **版本**：0.1.0，里程碑 M2
- **优先级**：`[A] / P0`
- **前置依赖**：[个人缓存](01-个人缓存与持久化.md)、[供应链坠](02-供应链坠与网络绑定.md)
- **兼容测试基线**：JEI `19.51.0.418`；不是加载器依赖，每轮兼容矩阵前重新核实适用的 1.21.1 最新版
- **被依赖**：补货状态、合成来源偏好、手动重置
- **规格状态**：2026-09-05 起受缓存归属与升级重构影响而暂停；界面交互和精确组件规则可作参考，旧材料等级、玩家全局阶段、MVP 简化工艺与手持升级行为已失效

> **当前覆盖规则：** 玩家可见等级为 1—5 级，依次对应 9／128／1、16／256／2、24／512／3、30／1,024／4、36／2,048／5（格数／单格容量／插件槽）。等级归当前缓存，永久升级走 Create 序列组装。项目尚未发布，旧 `STONE` 等等级名、旧升级件 ID 和旧测试 schema 不提供兼容。完成本规格的整体重写和新 schema 实施授权前，不得据下方历史段落继续编码。

## 用户故事

> 作为佩戴供应链坠的玩家，我希望背包左侧出现一组像真实库存一样可取可存的大容量物流格，并能在每格角落设置最低／最高数量。

> 作为逐步升级的玩家，我希望格数和单格容量按五个阶段明确增长，旧物资和旧配置在升级后原位保留。

## 范围与明确排除

本规格包含原版生存与创造背包页入口、两列物流格、原版鼠标语义、精确组件过滤及安全拒绝、双端设置、状态反馈、来源开关，以及五阶段数值和 `v0.1.0` 简化升级工艺。缓存事务、网络绑定、Create 发单、包裹处理、合成取料和弓弩消费由对应规格决定，界面只提交意图与显示服务端快照。

本规格不为工作台或第三方容器添加常驻物流面板，不实现退货上箭头、TaCZ、护甲入口、第三方背包插件或正式序列组装。

## 显示入口

面板附着在原版生存 `InventoryScreen` 和创造 `CreativeModeInventoryScreen`：

- `localAccess=ACTIVE` 时显示物流格、阶段、来源开关、网络／配送状态和折叠按钮。
- `localAccess=MANAGEMENT_ONLY` 时以终端管理面板替代物流格；异网冲突时可禁用／清绑，全部禁用时可重新启用／清绑。
- `localAccess=INACTIVE` 时不渲染任何本模组按钮、格子、状态或 tooltip。
- 工作台、箱子和其他容器不显示该左侧面板；合成取料通过各自菜单与配方入口工作。
- 创造物品目录中的栈只可作为 ghost 模板设置过滤，不作为真实物资存入缓存；服务端保留其物品 ID 与完整持久化组件，完成 1,024 字节及往返校验后建立 0 库存精确过滤。创造背包标签中的玩家真实库存仍按服务端原版库存槽处理。

玩家仅把供应链坠放进普通背包时等同 `INACTIVE`。只有实际 Curios 槽中仍有坠子时，全部禁用状态才显示最小管理入口。

## 面板布局

### 首选布局

- 面板内容宽 42 px，外框宽 50 px；锚点为原版背包 GUI 左边缘向左 56 px、顶部向下 7 px。
- 格子为 18×18 px，两列、五个可见行，按行优先编号：0 在左上、1 在右上。
- 1 级第 5 行只启用左格；右格绘制锁定占位，不接受鼠标。
- 16／24／30／36 格仍为两列，通过垂直滚动查看；滚轮一次移动一行，滚动条拖动按行吸附。
- 面板顶部显示阶段徽记和 `已用格/总格`；底部显示来源优先级开关、网络状态和折叠按钮。

### 空间不足布局

若首选面板左边缘小于屏幕安全边距 4 px，则改成左侧抽屉：抽屉从屏幕 x=4 展开，覆盖游戏背景但不覆盖原版 GUI 槽；原版 GUI 向右不移动。若抽屉与 JEI 可用区域重叠，先折叠为 14×22 px 标签按钮，由玩家点击临时展开。折叠只影响显示，不停用服务端自动能力。

数量设置不再打开居中模态框。小型双端滑条直接贴在当前物流格下方绘制；下方越界时改放在该格上方，水平方向只做屏幕安全边距内的钳制。点击滑条外部会关闭它并继续原界面操作，Esc 只关闭滑条而不关闭背包。

## 单格视觉

| 区域 | 位置 | 内容 |
| --- | --- | --- |
| 物品 | 中央 16×16 | 空格不画；已有过滤但库存 0 时以 50% 透明度画完整精确模板，保留名称、附魔光效与组件 tooltip |
| 数量 | 右下 | 0 不写；1—999 写整数；1,000 以上写一位小数 `k`，tooltip 显示精确整数 |
| 设置点 | 右上视觉 4×4、命中区 8×8 | 悬停该格时出现；空光标且未拖拽时点击，或键盘聚焦后按 Enter／Space，打开格下小型双端滑条 |
| 状态 | 左下 6×6 | 下箭头或阻塞符号；颜色之外还有形状和 tooltip |
| 选中框 | 外沿 | 当前设置格、重复过滤原格、错误格使用不同轮廓 |

状态图标不接受点击。设置点的 8×8 命中区只在空光标、未进行快速拖拽时启用；携带物品时整格仍是存入／设过滤目标，不能被隐藏热区截走。鼠标不在命中区时遵循库存语义；键盘焦点轮廓必须可见。

## 鼠标与键盘语义

把物流格视为“过滤固定、显示栈最多为物品原生上限、后面还有内部余量”的槽：

| 操作 | 结果 |
| --- | --- |
| 空光标左击有货格 | 取出 `min(原生堆叠上限, 缓存数)` 到光标 |
| 空光标右击有货格 | 取出上述显示栈的一半，向上取整 |
| 精确同变体光标左击已有过滤格 | 尽量把光标整栈存入，受实际容量限制 |
| 精确同变体光标右击已有过滤格 | 存入 1 件 |
| 可安全编码实物拖入空格 | 同一事务建立完整组件过滤并存入实际可容纳量 |
| JEI 物品拖入空格 | 只建立过滤，库存保持 0 |
| Shift 左击物流格 | 本次最多转出一个“显示栈”，即 `min(原生堆叠上限, 缓存数)`；按原版顺序并入玩家主物品栏／快捷栏，放不下的部分留缓存 |
| Shift 左击普通背包物品 | 生存界面只有已有匹配过滤格时才存入；创造背包标签中的玩家真实库存没有匹配格时，可占用第一个已解锁空格并在同一事务建立过滤和存入实物 |
| 双击同变体 | 在光标原生上限内，从当前界面的普通背包和该唯一精确变体格收集；同 ID 异组件不参与 |
| 数字键／交换副手键 | 不把千级内部数直接塞入目标；只转移一个合法显示栈，目标不能接收则无变化 |
| 不同物光标点击非空过滤格 | 不交换、不改过滤，提示必须先取空 |
| 空光标 Shift 右击 0 库存过滤格 | 清除过滤；与滑条内 Delete 相同，库存非 0 时拒绝 |

鼠标快速拖拽分配不跨多个物流格：同一精确变体只允许一个过滤格，跨格分配没有第二个合法目标。同 ID 异组件按各自过滤处理；普通背包槽仍保持原版快速拖拽行为。

所有取存都由服务端按实际可移动量提交。客户端动画、光标预测和重复点击不能改变数量。

## 空格设定与精确组件

### 背包与 JEI 来源

- 背包来源：服务端从实际来源栈取得数量为 1 的完整组件模板；设置过滤与存入实物是一个事务，提交前来源身份或数量变化则全部失败。
- JEI 来源：发送有界 ghost 模板，服务端完整保留其组件，`storedCount` 保持 0；客户端不能借此生成实物。
- 完全相同变体已在别格：拒绝新格并高亮已有格，背包来源保持原样；同 ID 但组件不同的变体可独立建格。
- 滑条打开时可按 Delete 清除过滤；格子悬停时也明确提示可用 `Shift + 右击` 清除 0 库存过滤。只有 `storedCount == 0` 时可用；提交成功时关闭双端并清除该旧物品的本地待收记账，世界中的真实旧包不受影响。之后才能向该格设置另一物品。

### 组件显示与安全拒绝

带组件物品按完整状态直接设格，不弹出“改为默认模板”的二次确认。名称、耐久、附魔光效、气量和第三方 tooltip 均来自服务端确认的完整模板。组件发生变化后，光标实物不再匹配原格；界面提示“组件状态与此格不一致”，已有对应格时高亮对应格。

模板无法完整往返编码时显示：

> 该物品数据无法安全存入物流缓存。

规范模板超过 1,024 字节时显示：

> 该物品数据过大，无法存入物流缓存。

两种拒绝均保持光标／来源、目标格和缓存不变；不能提供“仍然存入”或“去除数据”按钮。

包裹外壳不允许成为普通物流过滤。

## 格下双端滑条

滑条使用 Create 的黄铜、深棕、灰色凹槽与像素倒角语言，宽度只覆盖当前格附近，不再遮住大面积背包。它包含一条 0—当前单格容量的共用轨道、最低端、最高端和两端数值；精确状态与操作说明放入悬停提示，不常驻展开说明区。

### 默认与启用

- 新格最低端显示在 0，`enabled=false`。
- 新格最高端显示在当前容量，`enabled=false`。
- 拖动端点、滚轮调值或确认数字输入会自动启用该端。
- 右击对应端点可单独关闭／开启；关闭最低端时立即规范化为 `{enabled:false,value:0}`，关闭最高端时立即规范化为 `{enabled:false,value:当前容量}`，不保留隐藏的旧活动值。
- 升级时，已启用端的数值原样保留；关闭的最低端归一为 0，关闭的最高端归一为新容量。

### 数值规则

- 拖动按整数；按住 Shift 拖动按 8 为步长，滚轮每格 1，Shift+滚轮每格 16。
- 点击端点下方数字进入紧凑数字输入，只接受 `0..capacity` 十进制整数；Enter 或失焦提交，Esc 恢复服务端值并退出输入，第二次 Esc 关闭滑条。
- 两端都启用时要求 `minimum <= maximum`。拖动穿越另一端时停在另一端；数字输入越过时拒绝并保留旧值。
- `N < minimum` 才有正缺口；`N == minimum` 不发空请求。
- 最高端是退货目标，不是存储容量。0.1.0 保存并显示它，但不创建退货包；设置框明确写“退货将在后续版本启用”。

### 按格重置

滑条打开时按 `R` 发起“重置本格待收”，悬停提示列明物品和待收数量；再次按 `R` 确认。确认只清该过滤物的本地待收，不改现货、包裹或网络。待收为 0 时无操作。

## 来源优先级开关

面板底部小开关只有两个值：

- `背包优先`：新记录默认；先用手中明确物品，再用普通背包，再用缓存。
- `缓存优先`：先用手中明确物品，再用缓存，再用普通背包。

“手中明确物品”保持最高优先级，因为产品边界不覆盖玩家直接用手作出的来源选择。开关只改变已支持的合成／弹药选源，不搬物资、不改变补货只统计缓存的口径。偏好归玩家，换坠子、死亡和重启后保持。

## 状态图标

0.1.0 使用以下下行状态；退货上箭头在 0.2.0 实现前不显示为可用状态。

| 优先级 | 条件 | 图标 | Tooltip 核心文字 |
| ---: | --- | --- | --- |
| 1 | 背包内有该物品的本模组专用残包 | 包裹加暂停角标 | “已到货，缓存腾位后继续接收；手动拆包或移走后提示消失” |
| 2 | 该物品待收量 > 0 | 绿色实心下箭头 | “已请求 X，等待本地到货；不代表载具位置” |
| 3 | 有未覆盖缺口且未绑定 | 灰色断开下箭头 | “需要 X；供应链坠未绑定网络” |
| 4 | 有未覆盖缺口且异网冲突 | 灰色交叉下箭头 | “不同网络冲突；先禁用一件供应链坠” |
| 5 | 有未覆盖缺口且网络不可见／缺货／忙碌／物品身份无法安全匹配 | 灰色下箭头加对应角标 | 显示本模组实际知道的原因与下次重检条件；身份不安全时不发单 |
| 6 | 无缺口 | 无图标 | 数量 tooltip 仍显示现货、阈值和容量 |

同一格只有一个主图标，tooltip 可以列出待收和其他诊断原因；不能用灰色一项掩盖更具体原因。残包图标来自当前主物品栏的有界扫描结果，不保存固定槽号；包被手拆、移走或耗尽后最迟 20 tick 消失。

2026-09-03 起，补货沿用原生运输，不显示“无配送提供者”“玩家不具备运输资格”等需要探测外部运输才能得知的状态。不检测定位器、蜂成员或路线；请求后未到货仍是本地待收，不证明载具已出发，也不按超时自动改成丢件。

不属于单一物流格的收包错误显示在面板顶部网络状态下方：事务日志背压显示“等待安全保存后继续收包”，畸形包或收据不匹配显示包所在原版槽号及稳定错误文字。提示不得展示完整第三方组件，也不得提供“强制吞包”按钮。

## 输入与输出

客户端发送的 UI 意图只包含格号、操作类型、必要数值、受控菜单槽定位和预期玩家缓存修订号。JEI ghost 还包含由 JEI 插件解析出的物品 ID，但服务端必须重新查注册表。

服务端返回：操作状态、实际移动量、新修订号、变更格快照、阶段、容量、来源偏好和新的状态诊断。失败时客户端用服务端快照覆盖本地预览。

## 边界条件

- 1 级 9 格：第 5 行右侧不接收点击、JEI 拖入或键盘交换。
- 滚动时正在拖拽物品：锁定滚动位置，放下或取消后才滚动。
- 滑条打开后该格被服务端改变：提交旧修订失败并刷新，不覆盖新值。
- 升级时滑条打开：保持同一格索引，用新容量重绘；若该格不再可见则关闭滑条。
- 缓存达到容量仍允许取出；存入只接受实际空余。
- `maximum < storedCount <= capacity` 在 0.1.0 是合法库存，只显示“超过退货上限，退货尚未启用”，不吞物。
- JEI 缺失：没有 ghost 拖入；背包实物设过滤和其余界面完整工作。
- GUI 极窄：使用折叠标签；不得把格子绘制到屏幕外或覆盖原版槽后仍接受隐藏点击。

## 技术 Spike

### `SPK-UI-01`：InventoryScreen、配方书与 JEI 布局

在目标版本组合上实现只读假数据面板，跑 4 个分辨率 × 5 个 GUI 缩放状态 × JEI 开关，共 40 组环境。每组内部再分别操作配方书关闭与开启场景，但不把场景数另算成环境组合。输出每种锚点、可用矩形与截图；不删减两列、五行可见区、滚动、折叠或数字输入。

### `SPK-JEI-01`：Ghost ingredient

验证届时最新的 Minecraft 1.21.1 NeoForge JEI（当前实现基线 `19.51.0.418`）中 `IGhostIngredientHandler` 的拖入坐标、完整子类型组件、取消行为和服务端有界模板校验。插件只提交 ghost 模板意图，不通过 JEI 取出物资，也不要求加载器预先声明 JEI；同 ID 的两个 JEI 子类型必须建立不同过滤。

## Given / When / Then 验收

1. **Given** 未佩戴供应链坠，**When** 打开背包，**Then** 没有任何本模组像素或隐藏点击区。
2. **Given** 1 级缓存，**When** 打开面板，**Then** 两列五行中只有 9 格可用，第 10 格锁定，并且只有 1 个通用插件槽可用。
3. **Given** 5 级缓存，**When** 滚到底，**Then** 可访问 36 格，格号稳定且没有压缩重叠，并且共有 5 个通用插件槽。
4. **Given** 缓存有 2,048 件但物品原生上限 64，**When** 左击取出，**Then** 光标最多 64，缓存剩余 1,984。
5. **Given** 背包有 20 个相同精确变体的石头，**When** 拖入空格，**Then** 完整过滤建立、背包减 20、缓存加 20。
6. **Given** 从 JEI 拖石头，**When** 放入空格，**Then** 过滤建立、缓存仍为 0、没有物品生成。
7. **Given** 满气与半气铜背罐，**When** 分别拖入空格，**Then** 两个精确组件模板分别显示并可独立占格；把半气背罐拖到满气格时不移动并提示组件不匹配。
8. **Given** 另一格已有完全相同变体过滤，**When** 背包或 JEI 向空格设置，**Then** 新格不变并高亮原格；同 ID 异组件不被误判重复。
9. **Given** 格内仍有 1 件，**When** 尝试清过滤或换物，**Then** 拒绝且不吞物。
10. **Given** 新格，**When** 尚未操作滑条，**Then** 最低 0／最高容量均显示为关闭，不发单也不退货。
11. **Given** 最低 128、缓存 128，**When** 评估，**Then** 不发空订单；取出 1 后缺口为 1。
12. **Given** 最高 100、缓存 120、实际容量 128，**When** 0.1.0 运行，**Then** 120 合法保存，只提示后续退货，不删除 20。
13. **Given** 2 级缓存，**When** 经最终定案的 Create 序列成功提升到 3 级，**Then** 原 16 格与既有插件逐字段不变、追加 8 个空物流格和 1 个空插件槽；预览或未完成序列不改变缓存。
14. **Given** 当前阶段不匹配或访问冲突，**When** 使用升级件，**Then** 不消费、不升级。
15. **Given** JEI 和配方书开启、窗口 854×480，**When** 展开面板与格下滑条，**Then** 所有控件可达，原版槽和 JEI 搜索／分页不被不可逆遮挡。
16. **Given** 玩家设置缓存优先，**When** 换坠子、死亡、重连，**Then** 开关保持；卸下期间不参与原版操作。
17. **Given** 缓存有 2,048 件且原生上限 64，**When** Shift 左击一次，**Then** 本次最多向背包转移 64，背包空间不足时只扣实际接收量。
18. **Given** 最低 128 已启用、最高 512 已启用，**When** 分别关闭两个端点，**Then** 服务端值立即变为关闭的 0／当前容量；重新打开界面没有隐藏旧阈值。
19. **Given** 玩家处于创造模式，**When** 打开任一创造标签，**Then** 面板与生存模式访问同一份服务端个人缓存；从创造目录携带的物品只能设 ghost 过滤，不能增加缓存现货。
20. **Given** 玩家在物流格按下后服务器于松开前同步光标栈，**When** 原版界面处理鼠标释放，**Then** 本模组已经消费的按键释放不会再被原版解释为 GUI 外丢弃。
21. **Given** JEI 提供一个带弹种组件的子类型，**When** 拖入空格，**Then** 服务端快照回显完整子类型、库存为 0；关闭再开界面后身份不变。
22. **Given** 模板规范编码为 1,025 字节，**When** 从背包或 JEI 拖入，**Then** 显示 `ITEM_TEMPLATE_TOO_LARGE`，不出现二次确认或去数据入口，来源和目标格均不变。
