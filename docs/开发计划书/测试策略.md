# 测试策略

- **计划版本**：plan-v1.0
- **目标发布**：`v0.1.0`
- **当前状态**：`test.9—12` 只作旧模型证据；2026-09-05 新缓存模型、1—5 级与插件舱测试策略待重写，受影响验证暂停

> **当前覆盖规则：** 新模型只验证干净 schema 的首次创建、保存重载、坏数据拒绝和物资守恒，不编写旧 `test.N` schema 迁移夹具或兼容测试。精确组件身份相关测试仍保留；下方 schema 1→2 条目只记录已经完成的历史测试目标，不再作为首个正式版本完成门。

## 1. 验证原则

1. 物资守恒、权限和幂等是零容忍门槛；截图或“看起来能用”不能替代计数证据。
2. 先测纯领域规则，再测 Minecraft 服务端事务，最后测真实 Create 工厂与两种运输载具。
3. 单装纸飞机、单装运输蜂和二者共存必须分别完成真实闭环；不能用替身或另一种载具代替。
4. 所有运行测试使用隔离存档与测试账号，不接触玩家真实存档。
5. 每份结果注明构建、模组清单、Java、测试入口、通过／失败和未覆盖边界。

## 2. 验证层级

| 层级 | 负责证明 | 不负责证明 |
| --- | --- | --- |
| 文档静态检查 | 链接、版本、规格状态、任务依赖和数值一致 | 编译、运行或兼容 |
| JVM 单元／属性测试 | 阶段表、阈值、来源分配、事务计划、限额和错误码 | NeoForge 生命周期与第三方行为 |
| GameTest Server | 玩家附件、物品栏、菜单、包裹组件和服务端提交 | GUI 可操作性和真实外部载具寻路 |
| 客户端人工／自动辅助 | UI、鼠标键盘、JEI、配方书、视觉状态 | 专服类加载与多人隔离 |
| 独立服务器 | 客户端／服务端边界、权限、多人隔离、保存重载 | 单机 UI 全矩阵 |
| 真实运输验收 | Create 扣库、打包、纸飞机／蜂投递和残包 | 本模组以外的所有运输故障恢复 |
| 性能与故障注入 | 有界扫描、退避、保存切点和恢复封锁 | 任意硬件上的绝对性能承诺 |

## 3. 自动测试目录

### 3.1 领域单元与属性测试

至少覆盖：

- 五阶段只能逐级升级，格数和容量为 9／128、16／256、24／512、30／1,024、36／2,048；关闭的最低／最高端始终规范化为 0／当前容量；成功升级在生存消费 1、原版 `instabuild` 创造模式消费 0。
- `N < L` 时缺口为 `L - N - P`，等于最低时为 0；最高端不影响首版补货。
- 同一 `ItemVariantKey` 过滤唯一，同 ID 异组件可分别占格；组件编码往返、存取、请求、收包和消费保持完整身份。Create 网络混存同 ID 变体时只查询和请求目标精确变体，API 无法区分时不发单；1,024／1,025 字节边界、负数、溢出和越界输入整笔验证。
- 背包优先／缓存优先的混合分配在所有来源不足组合下守恒。
- 每物品 4 条、全玩家 144 条待收上限；安全合并、归零删除和手动重置不产生历史膨胀。
- 事务日志在 256 条／256 KiB 任一上限前逐包提交，上限处背压且原包不变；一次成功保存后只清理可证明已保存的终态条目。
- 重复 `expectedRevision`、重复收据和重复包扫描满足幂等。
- schema 1 固定夹具迁移到 schema 2 后逐字段保持；重复加载幂等、未知物品封锁、失败不以空记录覆盖，跨 JVM 回读与死亡复制均通过。
- 随机生成存入、取出、合成、收包、升级和重置序列，逐步断言所有物品总量、容量和不变量。

### 3.3 故障注入

包裹收包事务在 `PREPARED`、包裹减少后、缓存增加后、`COMMITTED` 四个切点分别强制中断并重载。每次记录包裹内容、缓存、待收、收据和整包事务日志；`包裹内实物 + 缓存现货` 必须等于中断前基线或完整提交后的等量转移结果，不能增加或减少。对人工伪造的未知非终态日志可以只读封锁，但四个正常切点不能用“已报警”掩盖物资损失、复制或自动猜测完成。

## 4. 客户端 UI 矩阵

物流面板在 854×480、1280×720、1920×1080、2560×1440 四种窗口下，分别以 GUI 缩放“自动、1、2、3、4”验证；每组再跑 JEI 关闭／开启，共 40 组。每组检查：

- 两列布局、9 格末行单格、滚动和折叠入口均可达。
- 原版配方书、JEI 搜索与配方区域、物流格和 tooltip 不互相遮挡。
- 左／右／Shift 点击、拖动、滚轮、数字输入、Tab 焦点和 Escape 关闭符合规格。
- 状态不只靠颜色；待收、网络不可见／缺货／忙碌、未绑定、物品身份不安全、残包、异网冲突和全部禁用管理态有不同图形与文字；不猜测外部运输资格或定位器状态，完全未佩戴时没有隐藏点击区。
- 带组件实物一次操作即可建立精确过滤并真实转入；同 ID 异组件分别显示，组件不匹配提示明确。超大／不安全模板一次拒绝且没有去数据二次确认。

截图文件名固定为 `C<组合>-<分辨率>-gui<缩放>-<场景>.png`，并在验证记录中索引。

## 5. 依赖与启动矩阵

发布基线固定为 NeoForge 21.1.219、Create 6.0.10、Curios `9.5.1+1.21.1`。以下六组客户端和专服都必须启动：

| ID | JEI | 纸飞机 | 运输蜂 | 功能门 |
| --- | --- | --- | --- | --- |
| C0 | 无 | 无 | 无 | 缓存、配方书、标准投射物弹药可用；有效 Create 绑定下可请求真实包裹，自行取得的匹配包可入库 |
| C1 | 有 | 无 | 无 | 增加 ghost 与 JEI 转移；不因未安装运输模组阻止 Create 请求 |
| C2 | 无 | 有 | 无 | 纸飞机完整包闭环 |
| C3 | 无 | 无 | 有 | 蜂成员资格与完整包闭环 |
| C4 | 有 | 有 | 有 | 全入口共存；一个缺口一个请求 |
| C5 | 无 | 有 | 有 | 双运输不依赖 JEI |

另有两个预期失败测试：缺 Create 或缺 Curios 时，加载器必须用依赖声明拒绝启动并指出缺失依赖，而不是运行后崩溃。Create 6.0.11 只跑探索矩阵，结果不写入 `v0.1.0` 兼容声明。

## 6. 独立服务器与多人

至少两名真实客户端加入隔离专服，覆盖：

1. A、B 各自缓存、阶段、偏好和待收隔离；交换已绑定坠子只交换其网络配置，接收者可用该 Create 绑定。
2. A 的地址包不会进入 B 的缓存；伪造地址、玩家名或 payload 不能选择他人缓存、创建绑定或伪造蜂成员资格。
3. 两人竞争同一网络库存时，只按各自真实请求承诺记账，不出现负库存或免费物资。
4. 打开界面后卸坠、禁用、产生异网冲突或断线，旧意图全部安全拒绝。
5. 正常保存、停服、重启后，两个玩家逐字段一致；专服日志无客户端类加载。

## 7. 双运输真实验收

每条路线都使用实际 Create 仓储、Stock Link、打包机和该提供者的玩家投递设施：

1. 工厂库存分别设为 0、部分和足量，记录请求返回、网络扣库、生成包数与内容。
2. 只安装纸飞机，按原生设施、定位器及配置选择完整包模式，完成同维度、跨维度、背包有空间／全满、卸坠／重装；FMP 不修改原生目标。
3. 只安装运输蜂，覆盖网络成员／非成员、同维度、跨维度、发货区块加载／卸载、背包有空间／全满。
4. 同时安装两者，分别让每条工厂路线独立成功，再让两者都可用，确认同一缺口只广播一次。
5. 包只装入一部分时核对余物、地址、订单组件与收据；手拆或移出残包后下一次扫描不保留假等待。

外部载具未送达只记录为运输结果；本模组不自动赔付。测试人员可以按格重置后重新请求，并核对新请求再次真实消耗网络库存。

2026-09-03 用户报告现有补货不需要专用适配。T08／T09 先收集已有构建版本、搭建方式和结果，只补缺项；不把用户一次实测扩写为全矩阵通过，也不为凑实现交付物增加适配器。原生规则不允许跨维度或成员条件未满足时，验收的是未越权、未虚记到货和实物去向，而非要求 FMP 绕过限制送达。

## 8. 性能测试

按[非功能需求](非功能需求.md)固定场景运行 100 人无人佩戴、空闲佩戴、20 tick 兜底扫描、集中变化和缺货阻塞。记录硬件、JVM 参数、模组清单、预热、10 分钟统计窗口、tick p50／p95／p99、扫描次数、请求次数和快照字节数。

客户端在坚固板阶段 36 格、每格填入接近 1,024 字节的不同精确模板且 JEI 开启时，对比开面板前后帧时间并测量完整快照仍小于 64 KiB；滑条连续拖动 10 秒，验证 C2S 不超过每 tick 一次且松开立即提交最终值。

## 9. 计划命令与登记规则

工程已建立，以下入口已登记并在 T00—T04 使用；各任务的准确组合、退出码、数量和日志以[开发状态](../开发状态.md)为准：

```powershell
.\gradlew.bat test
.\gradlew.bat runGameTestServer
.\gradlew.bat runClient
.\gradlew.bat runServer
.\gradlew.bat build
```

GameTest Server 配置 `setForceExit false`，让失败返回非零退出码。每个命令保存退出码与报告路径，不能只截取末尾“BUILD SUCCESSFUL”。
