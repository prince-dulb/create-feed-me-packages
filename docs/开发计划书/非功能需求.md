# 非功能需求

- **计划版本**：plan-v1.0
- **目标发布**：0.1.0
- **适用范围**：旧 plan-v1.0 非功能基线；新模型沿用守恒、安全与性能原则，缓存所有权、1—5 级、插件舱和持久化场景待重写

> **2026-09-05 覆盖规则：** 新模型不承担旧 `test.N` schema 或注册 ID 的存档兼容，不运行旧格式迁移验收；只验证干净 schema。下方与 schema 1→2、玩家唯一缓存或材料等级名有关的指标降为历史，不得阻塞或指导新实现。

## 1. 正确性与物资守恒

这些指标没有“可接受误差”：

1. 自动测试和游戏内验收中，本模组引起的物资复制、静默丢失、负数库存、超容量库存均为 0 次。
2. 每个提交事务满足：`来源减少量 = 目标增加量 + 原操作明确消耗量`。模拟、失败、取消和旧修订请求的三项都为 0。
3. 同一客户端意图、包裹插入通知、物品栏变化或周期扫描重复执行，最终结果与执行一次相同。
4. 玩家死亡、维度切换、断线、重连、服务器正常重启后，个人缓存逐字段一致；`keepInventory` 开关不改变缓存。
5. 同网多件供应链坠不会多算容量或重复发单；异网冲突时除冲突管理外的成功事务为 0。
6. 包裹装不下时，缓存增加量严格等于包裹内容减少量，余物和全部组件留在原包。
7. 存取、Create 查询／请求、收包、合成与弹药消费必须保持同一完整 `ItemVariantKey`；不得把同 `itemId` 的其他组件变体合计、输出为默认实例或结算到错误待收。无法证明精确匹配时请求量为 0，并给出稳定阻塞状态。
8. 手动重置只改变该物品的待收数量；缓存现货、网络库存、世界实体和迟到包不被修改。
9. schema 1 → 2 迁移不得改变任何库存数量、阈值、格位、阶段、偏好、请求／收据身份或总修订号；失败时不得覆盖为新空记录。

任何一项失败都阻止 0.1.0 交付，不能用配置开关隐藏。

## 2. 性能预算

### 2.1 服务端

性能场景在同一隔离专服、固定 JVM 参数和固定测试存档中对比“安装本模组但无人佩戴”基线。测试记录硬件、Java 构建、模组列表和统计窗口。

| 场景 | 负载 | 门槛 |
| --- | --- | --- |
| 无人佩戴 | 100 个在线测试玩家，10 分钟 | 本模组不创建周期包扫描；相对未安装基线的服务器 tick p95 增量小于 1 ms |
| 空闲佩戴 | 100 人均佩戴、36 格配置完成、无库存变化，10 分钟 | 本模组总 tick p95 小于 2 ms；不得触发 Create 发单 |
| 兜底扫描 | 100 人、每 20 tick 扫 36 个主物品栏槽 | 单次全体扫描 p95 小于 5 ms；不扫描末影箱、世界实体或第三方背包 |
| 集中变化 | 100 人同 tick 各取出 10 次同物品 | 每玩家同物品的缺口评估合并为 1 次；同一缺口 Create 广播不超过 1 次 |
| 缺货阻塞 | 100 人各有 36 个缺货格，10 分钟 | 同一玩家／物品重检间隔不短于 100 tick；不存在每 tick 空订单 |
| 初始同步 | 坚固板阶段 36 格全部配置，每个模板接近 1,024 字节 | 单玩家初始 S2C 快照编码后小于 64 KiB |

任何本模组单次主线程任务不得主动等待磁盘、网络或区块加载。外部 API 会触发区块加载时，Spike 必须改用已加载对象查询或停止该功能路径。

### 2.2 客户端

- 36 格面板只渲染可见行及一行缓冲，不为锁定或不可见格重复构造 tooltip。
- 在 60 FPS 基线下，打开坚固板阶段面板后的渲染帧时间 p95 增量小于 2 ms；测试同时覆盖 JEI 开启。
- 滑条拖动只更新本地预览；每 tick 最多向服务端合并发送一次该格最终值，松开鼠标立即提交一次。
- 数字输入、滚轮和拖动共享同一校验，不产生越界中间值或日志刷屏。

## 3. 容量与资源上限

| 资源 | 上限 |
| --- | --- |
| 每玩家缓存格 | 36 |
| 每格 0.1.0 现货 | 2,048 |
| 单个 `ItemVariantKey` 规范编码 | 不超过 1,024 字节；数量固定为 1，完整组件往返后身份不变 |
| 每玩家未完成待收记录 | 每个已配置精确变体最多 4 条、总计最多 144 条；正常调度在创建第 5 条前合并同变体记录 |
| 待收诊断历史 | 不持久化；完成／手动重置后从活动表移除，只写结构化日志 |
| 每玩家活动包裹事务日志 | 256 条且编码后最多 256 KiB；提交并通过下一次玩家保存后清理终态条目，满时背压而不删数据 |
| 收货地址 | 最多 64 个 UTF-8 字节；首版实际格式不超过 `FMP@` 加 16 字符玩家名 |
| C2S 单包 | 小于 8 KiB，低于 NeoForge 32 KiB 上限 |
| S2C 初始快照 | 小于 64 KiB，远低于 1 MiB 上限 |
| 每玩家 UI 变更意图 | 持续不高于 20 次／秒；超出后合并同类意图并记录一次限流提示 |
| 每个打开菜单的合成转移 nonce 结果 | 最多 32 条，按提交顺序淘汰最旧项；菜单关闭即清除，旧请求仍须通过菜单状态与缓存修订复核 |

达到任一上限时拒绝新增状态并返回明确错误；不能截断现货、删除未完成请求或循环重试。

## 4. 安全与权限

1. 服务端从连接和当前 Curios 槽取得玩家与终端；任何 C2S 字段都不能选择他人 UUID、任意网络 UUID或任意容器。
2. 绑定只从玩家交互距离内、仍然存在的 Create Stock Link 读取真实网络 UUID，并服从服务器的方块交互保护结果。
3. 地址字符串只用于识别目的包；它不允许访问其他玩家缓存、创建饰品网络绑定或替代运输蜂成员资格。核心 Create 绑定随合法饰品转交，客户端裸 UUID 不构成绑定。
4. 每次提交重新检查佩戴、逐件禁用、异网冲突和菜单有效性；打开界面后卸下坠子会使旧请求失败。
5. 所有格号、数量、字符串、列表长度、枚举值、资源 ID 和物品组件模板在解码后、使用前校验；JEI ghost 模板不得超过 1,024 字节，异常 payload 可断开连接并给出稳定消息键。
6. 包裹内容最多 9 槽，每个非空内容栈必须满足自身原生堆叠上限；畸形包整包保留并拒绝，不能按合法前缀部分入库。
7. 可选兼容缺失时不加载其类。专服不得加载 `net.minecraft.client`、JEI 客户端或 GUI 类。
8. 结构化日志不打印完整任意组件、完整包裹内容或可能由第三方写入的自由文本。
9. 本项目 JAR 不包含第三方模组 JAR、源码或资产；许可证文件和依赖声明在发布包中可追溯。

## 5. 可靠性与恢复

- 所有修改在服务端主线程完成；异步任务只可做纯计算，提交前必须返回主线程重检。
- 保存格式包含独立 `schemaVersion`。解码器接受 schema 1 并无损迁移为 schema 2；未知高版本数据进入只读封锁，不用默认记录覆盖。
- 加载发现负数、重复过滤、超容量、非法资源 ID 或未完成事务日志时，停止该玩家的物资操作，保留原数据并输出一条带玩家 UUID 和错误码的诊断；其他玩家继续运行。
- 正常停服、自动保存和玩家登出后，重载测试必须得到同一修订号、现货、过滤、阈值、阶段、偏好和待收。
- 本模组不判断外部载具丢失，不设置自动超时、赔付或重发。唯一恢复入口是玩家按格手动重置待收。
- 可选兼容模块失败时进入模块级 `UNAVAILABLE`，核心和另一个兼容模块继续工作；该模块同一异常每 60 秒最多记录一次完整堆栈。
- schema 1 → 2 已获用户明确迁移授权；实现提交必须包含固定旧格式夹具、重复迁移幂等、跨 JVM 回读、失败原档保留及旧待收／日志不重复结算测试。后续格式变化仍须另行取得授权。

## 6. 可用性与可访问性

- 颜色不是唯一状态线索。绿色／灰色箭头同时有不同方向、轮廓和本地化 tooltip；冲突和错误提供文字原因。
- 所有滑条数值可用鼠标拖动、滚轮和键盘数字输入完成；焦点顺序可从开关、格子、小点、两端数值到重置按钮完整遍历。
- 状态 tooltip 必须区分“已请求，等待本地到货”“网络不可见”“网络缺货”“未绑定”“物品身份无法安全匹配”和“打包机忙”，不把它们都写成“无法配送”。首版不探测外部运输，不虚构“没有完整包提供者”或“玩家不满足运输资格”等诊断。
- 带组件物品直接以完整精确模板设格；同 ID 异组件可辨认并分别占格。无法安全编码或超过 1,024 字节时一次拒绝、来源不变，不显示去数据或默认化二次确认。
- 冲突态保留每件供应链坠的缩短网络 ID、禁用按钮和清除绑定按钮；全部禁用态保留重新启用和清绑入口；完全未佩戴才不显示任何本模组控件。
- GUI 缩放为自动、1、2、3、4，窗口至少覆盖 854×480、1280×720、1920×1080、2560×1440。可操作区域不得超出屏幕；空间不足时折叠或滚动。
- JEI 和配方书同时开启时不能遮住物流格、搜索框、配方页切换或原版槽。实在无法同屏时，左侧面板提供明显折叠按钮，折叠不禁用服务端功能。

## 7. 国际化与文案

- 0.1.0 必须同时提供 `zh_cn` 和 `en_us`，任何面向玩家的文字都使用翻译键。
- 数量使用当前语言的千位分隔；内部、网络和存档始终使用整数，不解析本地化字符串。
- 正式名称固定为“供应链坠 / Supply Chain Pendant”。后续“供应链甲 / Supply Chainmail”和“供应链盔 / Supply Chain Helm”可预留翻译键，但 0.1.0 不注册物品。
- 地址、资源 ID、版本号和错误码不翻译；解释文字翻译。
- 缺失翻译键、格式参数数量不一致和英文硬编码扫描在构建检查中为失败。

## 9. 可测试性与可观测性

- 领域计算以纯函数形式覆盖：阶段表、阈值、缺口、待收抵扣、唯一过滤、来源分配和错误码。
- 本模组操作的边界通过接口注入：Create 网络、Curios 枚举、玩家槽与时钟。首版纸飞机、运输蜂按原生方式做实物交接测试，不为测试替身而新增运输适配层。GameTest 使用真实 Minecraft／NeoForge，单元测试使用受控替身。
- 调试日志为结构化单行，至少包含 `event`、`player`、`slot`、`item`、`count`、`networkShortId`、`revision`、`result`。
- 开发构建提供只读 `/feedmepackages audit <player>` 管理命令，输出不变量、活动待收、终端归并和兼容状态；正式构建保留该命令并要求权限等级 2。命令不修改数据，也不打印第三方完整组件。
- 每个发布候选保存：依赖清单、自动测试报告、GameTest 日志、客户端截图矩阵、专服日志和两种运输的人工步骤记录。

1. 编译、单元测试、GameTest Server、客户端启动、专服启动全部通过。

4. 性能预算在记录的测试环境内通过，没有每 tick 空订单或无界列表。
5. 中英文资源完整，GUI 缩放与 JEI／配方书矩阵可操作。
6. 发布 JAR 内容与许可证审计通过，第三方 JAR／资产／源码数量为 0。
7. `AGENTS.md` 已记录真实可运行命令；验证记录明确区分自动、客户端、专服和人工游戏内测试。
