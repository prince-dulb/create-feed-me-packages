- **计划版本**：plan-v1.0
- **首个目标发布**：`v0.1.0`
- **平台**：Minecraft 1.21.1 / NeoForge
- **状态**：旧 plan-v1.0 保留为 `test.12` 历史基线；2026-09-05 新缓存模型、1—5 级与插件舱重写中，受影响里程碑暂停

| Java | 21 | 构建与运行工具链 |
| Minecraft | 1.21.1 | 唯一游戏版本 |
| NeoForge | 21.1.219 | 必需 |

## 2. `v0.1.0` 的完成定义

首版不是单一路径原型，而是以下闭环同时成立：

1. 玩家通过 Curios 的供应链坠访问个人缓存；缓存、配置和阶段随玩家保存，坠子只保存一个网络绑定与禁用状态。
2. 五阶段严格为 9／128、16／256、24／512、30／1,024、36／2,048；同一“物品 ID＋完整持久化组件”精确变体只设一格，同 ID 异组件可分别设格，默认双端关闭；JEI ghost 保存精确 subtype 而不生成物资。
3. 缓存不足时，服务端按 `最低 - 现货 - 有效待收` 请求真实 Create 包裹；不直接生成物资，不自动判丢件。
4. 纸飞机与运输蜂分别把完整专用地址包裹送入玩家原版物品栏；本模组只把与精确过滤匹配且能容纳的物品原样转入，余物留在原包。
5. 原版 2×2／3×3 配方书与 JEI 配方转移可以混合调用背包和缓存真实原料；原版弓、弩可以按原版语义调用缓存箭矢。
6. 未佩戴时功能不可见且不可用；未绑定但有效佩戴时本地缓存和迟到包处理可用，新补货请求不可用；异网冲突时只保留管理入口。
7. [测试策略](测试策略.md)中的自动、客户端、专服、双运输和 C0—C5 兼容矩阵全部通过，且没有物资复制、静默丢失或越权访问。

退货、TaCZ、无 Curios 护甲入口、第三方背包插件、EMI 和正式序列组装不属于 `v0.1.0`。

## 3. `v0.1.0` 里程碑

### M0：实施准备与接口定标

**进入条件**：用户明确批准开始实现。

**工作**：记录执行授权边界，建立 NeoForge 工程，解析锁定依赖，完成 `SPK-DEP-01`、`SPK-DEP-02` 与初始许可证审计，登记真实构建、测试和启动命令。其余 Spike 在所属任务开始时先做最小实验，通过后才写正式实现。

**退出证据**：依赖报告、客户端与专服空载启动日志、三项 M0 Spike 记录、可运行命令、无可选模组时的类加载检查。后续任务的阻塞 Spike 失败时停在该任务，不以删减已确认首版功能绕过。

### M1：个人缓存与供应链坠

**工作**：实现玩家 Data Attachment、完整 `ItemVariantKey` 缓存事务、schema 1→2 无损迁移、阶段数据、供应链坠数据组件、Curios necklace 槽、绑定／清除／禁用、多终端归并和只读审计命令。

**退出证据**：schema 1 数据无损、幂等迁移且下一次成功保存写 schema 2；死亡、换维度、断线、重启和饰品转交后逐字段与组件一致；同网不叠加、异网冲突停用；全部禁用仍可从最小管理入口重新启用；未绑定佩戴仍可存取缓存；旧修订意图不能重复移动物资。

### M2：物流格界面与五阶段

**工作**：实现背包左侧两列面板、空间不足时折叠／滚动、完整组件过滤拖放、同 ID 多变体显示、双端滑条、来源优先级、按格重置和五阶段升级物品／简化配方。可安全编码的组件模板一次设格，不做默认化二次确认。

**退出证据**：五阶段数值、原版鼠标语义、9 格末行单格、拖动／滚轮／数字输入和 40 组窗口／缩放／JEI 开关截图矩阵全部符合规格；此阶段只证明 JEI 共存布局，ghost 行为由 M5 验收。

### M3：Create 请求与本地收包核心

**工作**：实现缺口计算、完整 `ItemVariantKey` 精确库存摘要与请求、请求承诺、待收合并与限额、`FMP@玩家名` 地址、物品栏有界扫描、包裹收据、部分入库、残包续收、事务日志和手动重置。

**退出证据**：使用真实 Create 打包链与受控本地收包样本；0／部分／足量库存、同 ID 多个精确组件变体、组件原样请求与部分收取、重复请求、重复扫描、满缓存、残包手拆、迟到包和四个保存切点均守恒。不安装运输附属也能请求真实包裹并在自行取得后正常入库；这不冒充 M4 的运输验证。

### M4：纸飞机与运输蜂原生运输联调

**工作**：按 2026-09-03 用户澄清，沿用 Package Couriers 与 Mobile Packages 原生派送，不预设专用适配器；整理已有实测，验证原生定位／成员条件、完整包模式、背包已满、跨维度、单装和共存。FMP 只负责 Create 请求与本地收包；使用玩家身上的零件／蜂发运留到 `v0.2.0`。

**退出证据**：两种载具分别完成真实工厂到玩家的完整包闭环，原生条件和版本有记录；共存时一个缺口只广播一次；移除任一或全部运输附属后 FMP 核心仍可启动、请求 Create 包裹和接收已取得的匹配实物。不以新增适配代码作为退出门。

### M5：合成、JEI 与投射物取料

**工作**：实现原版配方书 2×2／3×3 转移、保留完整 subtype 的 JEI ghost 过滤与 recipe transfer、来源优先和混合补足、精确组件候选与配方余物安全路径，以及标准投射物共享查询／消费适配；弓释放、弩装填与非原版 `ProjectileWeaponItem` 子类作为验收样本。

**退出证据**：JEI ghost 只设精确模板且不生物资；模拟／取消／纯查询不扣缓存；批量填充、精确组件候选与来源混用守恒；桶等余物不丢；弓只在实际射击时消费，弩只在成功装填时消费，发射不重复扣箭；未登记 ID 的标准链测试物品可无缝使用缓存弹药。

### M6：稳定化与本地交付

**工作**：跑完整测试与性能矩阵；补齐中英文资源、依赖说明、许可证、变更说明和验证记录；只在用户明确要求可测试交付时生成本地发布目录。

**退出证据**：`release/v0.1.0/` 包含唯一 JAR、依赖清单、变更说明和按验证层分类的记录；没有 P0／P1 缺陷。建立本地交付物不代表允许 push、打标签或上传平台。

## 4. 后续版本边界

| 版本线 | 固定目标 | 不提前带入 |
| --- | --- | --- |
| `v0.2.0` | 退货：最高数量、运输物格、返回地址、出发前可行性检查、真实包裹交接；纸飞机单独适配；蜂保留格内原蜂并派一次性蜂，交付或失去目标后销毁，失败原包当地掉落；先沿用原生选站与回退 | 不自建全局配送、不新增退货站、不判断丢件、不做串网专用逻辑 |
| `v0.3.x` | TaCZ 已验证弹种、无 Curios 的供应链甲／供应链盔及无损拆卸、精妙背包／Create 存储背包等插件式访问、EMI | 不以改写全部第三方消耗流程换取宽泛兼容 |
| `v1.0.0` | 以 Create 序列组装、中间产物和概率产出替换首版简化升级工艺；完成稳定存档与正式兼容声明 | 不改变个人缓存归属、真实包裹和物资守恒三条基础规则 |

每条后续版本线在进入实现前必须另写功能规格与验收，不反向扩张 `v0.1.0`。

## 5. 版本变更规则

- 已确认玩法只能由用户新决定修改；技术验证失败先阻塞对应里程碑，再记录证据和影响。
- 依赖升级、存档格式变化或兼容声明变化必须更新本文件、技术栈核查、测试矩阵和变更记录。
- 没有通过 [非功能需求](非功能需求.md)发布门的构建只能称开发构建，不能放入 `release/vX.Y.Z/`。
- 当前没有日期承诺。任务按依赖和验收推进，不用未经测量的工时数字掩盖技术风险。
