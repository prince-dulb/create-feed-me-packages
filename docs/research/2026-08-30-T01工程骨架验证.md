## 2. 构建路径故障与修正

项目目录名含 `!`。默认把 NeoForm 生成的 `neoforge-21.1.219.jar` 放在项目内 `build/` 时：

- JAR 内容完整，含 `FML-System-Mods: neoforge`、`META-INF/neoforge.mods.toml` 和 NeoForge 类；
- Java 命令行 classpath 也含该 JAR；
- FML 模组清单却没有 `neoforge`，随后报告所有模组缺少 NeoForge。

只把 Gradle `buildDirectory` 改到不含 `!` 的相邻目录 `../.fmp-build-safe/` 后，同一版本组合立即识别 NeoForge，并能启动专服。这证明故障位于当前 SecureJar／union URI 对 `!` 路径的处理，不是 JAR 损坏或依赖漏下。构建脚本使用相对路径，没有写入机器私有绝对路径。

早期为绕过原路径下 javac 无输出曾启用 Eclipse 编译器。安全生成目录建立后，默认 javac 可正常重编译 5,364 个 Minecraft 源文件；继续使用 ECJ 会改变合成 lambda 名称，使 Flywheel 客户端 Mixin 找不到 `lambda$new$8`。因此最终配置恢复 NeoForm 默认 javac，客户端随后通过。

## 3. 已执行验证

本机 Java 17 不满足目标。以下命令执行前都只对当前 PowerShell 进程设置：

```powershell
$env:JAVA_HOME = Join-Path $env:APPDATA '.minecraft\runtime\java-runtime-delta'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
$env:GRADLE_OPTS = '-Dhttps.proxyHost=127.0.0.1 -Dhttps.proxyPort=7890 -Dhttp.proxyHost=127.0.0.1 -Dhttp.proxyPort=7890'
```

代理参数是本机当前联网条件，不写入项目配置。其他环境能直连 Maven 时不需要设置 `GRADLE_OPTS`。

## 4. 依赖失败与可选缺失

使用受控 init script `gradle/verification/exclude-runtime-mod.init.gradle` 分别从开发运行 classpath 去掉一个必需模组：

| 探针 | 必须出现的加载器结果 | 结果／记录 |
| --- | --- | --- |
| 缺 Create | `create_feed_me_packages requires create 6.0.10 or above, and below 6.0.11`；`Currently, create is not installed` | 通过；`../.fmp-build-safe/reports/t01/missing-create.txt` |
| 缺 Curios | `create_feed_me_packages requires curios 9.5.1 or above, and below 9.6`；`Currently, curios is not installed` | 通过；`../.fmp-build-safe/reports/t01/missing-curios.txt` |

NeoForge 在这类已记录的加载失败后仍可能让 Java／Gradle 进程以 0 退出，所以探针按加载器诊断文本断言，不能只看退出码。

C0 没有安装 JEI、Package Couriers 或 Mobile Packages，客户端、专服与 GameTest 仍能启动；当前 JAR 也没有引用三者的 Java 类。这只证明**空兼容层缺失安全**，不证明以后加入的可选兼容实现安全，更不证明三个兼容已完成。
