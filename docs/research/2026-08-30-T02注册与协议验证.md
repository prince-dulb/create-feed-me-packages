### 1.2 数据组件不变量

`TerminalConfig` 固定当前 schema 1，要求非空 `terminalId`、可选 `networkId`、`disabled=false` 和 `revision=0` 默认值，并拒绝负修订或未知 schema。`PackageReceipt` 固定：

- 地址非空且最多 64 个 UTF-8 实际字节；不是按 Java 字符数近似限制；
- `arrivalCounts` 与 `allocatedCounts` 分别最多 9 个物品 ID；资源 ID 最多 256 个 UTF-8 字节；
- 到货计数必须为正，分配计数不得为负，分配键必须存在于到货映射且不得超过到货量；
- `firstSeenGameTime` 不得为负；映射按资源 ID 排序后保存，避免同一收据因输入映射顺序产生不稳定编码。

两条路径共用相同不变量：持久化 `Codec` 返回错误，网络 `StreamCodec` 在编码／解码边界抛出 `EncoderException`／`DecoderException`。包裹内容是否符合物品原生堆叠上限仍须 T08 在读取真实包裹和注册表时验证，不能由纯收据 codec 猜测。

## 2. 协议边界

C2S 只表达当前连接玩家的操作意图：请求快照、存取、设置／清除过滤、设置阈值、按格重置待收、设置来源优先级、逐件禁用和清除绑定。它们不含玩家 UUID、网络 UUID、`ItemStack` 或任意容器对象。过滤意图只带有界物品 ID及来源类型；服务端后续仍须以真实菜单槽或已安装配方查看器入口复核。

公共服务端处理器执行：

1. 从 `IPayloadContext` 取得实际 `ServerPlayer`；
2. 再次检查结构不变量，畸形意图使用稳定翻译键断开；
3. 比较玩家当前 `containerMenu.containerId`，旧菜单返回 `INVALID_MENU`；
4. T03—T05 尚未接入时返回 `FEATURE_NOT_READY`，不提交任何物资或配置变化。

S2C 初始快照有界为 36 个缓存格和最多 64 个终端摘要。每格只含有界资源 ID、`long` 数量、阈值、待收汇总和过滤修订；终端摘要可含网络 UUID，因为该方向只向当前玩家展示服务端已经枚举出的终端。客户端处理器目前为空，T05 才建立实际状态存储与增量刷新。
