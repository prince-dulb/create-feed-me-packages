# 自动取料兼容边界核查

项目：Create: Feed Me Packages! / 机械动力：喂我发包！  
核实日期：2026-08-29  
目标平台：Minecraft 1.21.1 / NeoForge  
性质：**公开源码的静态核查，不是编译、游戏内测试或兼容承诺。**

## 1. 输入与结论

用户明确要求自动取料覆盖原版合成、弓／弩箭矢和 TaCZ 弹药，目标是覆盖除玩家直接用手以外的物品消耗；第三方若需侵入式修改，先保原版。缓存仍持有真实现货，受有效佩戴与特殊数据物品限制，来源优先级由背包页开关控制。

**结论：原版弓弩有可研究的查询入口，完整扣料事务仍须验证；TaCZ 不能直接套用同一入口，也不能当作普通无数据材料。** 本次找到的 1.21.1 候选是非官方移植，须明确实际支持构建。TaCZ 目标保留，但当前只列技术闸门，不因源码中存在某个方法就宣称兼容完成。[原版查询入口][N2]、[移植仓库说明][T1]、[弹种数据][T3]

本核查不要求立即修改任何模组、枪包、配置、存档或构建环境。产品入口仍为[项目计划书](../项目计划书.md)。

**同日后续批注更新：** 首版合成入口包含原版配方书或 JEI 向原版 2×2／3×3 合成界面填料；JEI 拖入物流格设过滤是另一项功能，不能拿它代替配方填料验收。用户将特殊物品规则明确为“同一物品的默认过滤模板”，不做跨物品映射、不改来源实物；这不解决 TaCZ 删除 `AmmoId` 后失去弹种身份的问题，也不自动批准弹种例外。背包访问插件留到后续，不纳入初期版本。组件与运输的新证据见[双运输地址与退货入口核查](2026-08-29-双运输地址与退货入口核查.md)，本文下方的 TaCZ 方案仍为研究建议。

## 3. 原版弓弩：事实与推断

### 已验证源码事实

`LivingGetProjectileEvent` 在查询可用弹丸时触发，允许替换返回的物品堆叠；说明同时提醒了实际消费时缩减堆叠及客户端／服务端的一致性。它不是一个“库存已经成功扣除”的通知。[N2]

`ProjectileWeaponItem` 补丁保留对无限材料、箭矢不消耗判断和附魔耗箭计算的处理。因此不能把“调用一次查询”或“生成一个弹丸”直接解释成必须消耗一个缓存物品。[N3]

### 设计推断，不是已实现机制

可以优先研究以事件提供候选箭矢，再在真实装填／消费提交处完成一次库存转移的适配。单独返回一个复制的 `ItemStack` 不会自动扣减本模组独立计数；只在查询时扣减又会使反复查询和取消操作吞箭。是否能完全依靠现有事件，或还需范围明确的局部接入，必须通过原型证明。

弓与弩的生命周期不能混为一次“开火扣料”：弩在成功装入箭矢后已持有实物，后续射出不能再次扣缓存。未佩戴时禁止新的缓存访问，但不删除武器已经装入的物资。带药效等特殊数据的箭矢继续受物品允许策略约束，不能去掉药效后当普通箭入库。

## 4. TaCZ：三个独立的兼容问题

### 4.1 版本身份

本次核到的 1.21.1 NeoForge 仓库明确标为非官方移植，并提示旧版本物品数据不兼容。这里只选作研究候选，没有承诺支持全部 TaCZ 版本、枪包或存档，也没有进行版本迁移。[T1]

### 4.2 弹种不是纯物品 ID

所读 `AmmoItemDataAccessor` 将弹种存放在 `DataComponents.CUSTOM_DATA` 的 `AmmoId` 字段中，取弹匹配使用这个标识；设置弹种时还会处理该弹种的堆叠上限。删除这份数据会丢失有效弹种身份，不能作为“变成无 NBT 弹药”的兼容办法。[T3]

**与当前产品规则的冲突：** 缓存不直接接收特殊数据物品，而 TaCZ 普通弹药也依赖额外数据来表达种类。因此，“支持 TaCZ 弹药”既需要取料接口，也需要允许范围的明确解释。

**建议防线，尚未批准：** 若纳入 TaCZ，仅允许经过适配验证的稳定弹种模板，保留所需身份数据、按完整身份去重；附加名称、未知自定义状态、容器内容等不自动获准。不同弹种不能合并为同一格；同一弹种不能用第二个重复格绕过唯一性。不得把这一候选例外扩成通用 NBT 压缩。如果例外或接入方案未落实，TaCZ 保留为待完成目标，原版主线继续。

### 4.3 可用接口不等于可直接接入

所读枪械实现通过实体 `ItemHandler` 查询可用备弹，并在提取路径扫描匹配弹药或弹药箱；脚本 API 的取弹方法也依赖该入口。普通弹匣与背包直读的处理分开。因此仅接原版箭矢事件不够，仅修改一个扣料方法也可能漏掉装填前的有弹检查。[T4]、[T5]

**推断与边界：** 需要验证能否在明确的取料范围内提供缓存来源，同时覆盖检查、模拟和真实提取，不替换全局玩家库存来伪装所有模组都支持。保留原有装填、弹匣、射击与不消耗规则，不要求修改枪包为背包直读。本次没有穷尽该项目全部扩展点，不能据这些路径断言必然需要 Mixin、改上游代码或完全无法实现。

以下全部**未执行**；只有在用户批准实现、锁定版本和建立隔离测试实例后运行。

| 编号 | 反例／场景 | 验收目标 |
| --- | --- | --- |
| A01 | 原版查询反复触发，或客户端预测和服务端都触发 | 查询不扣缓存、不发放真实物品；最终提交最多扣一次 |
| A02 | 背包无箭、缓存有允许箭矢；再交换两处库存并切换来源优先级 | 原版弓弩可识别实际现货并按优先级取料；总量不足不透支 |
| A03 | 拉弓后取消、拉力不足、射击被取消 | 未完成实际消耗不损失缓存箭矢；不凭查询或取消请求补货 |
| A04 | 弩装填成功后换装、保存重载、射出 | 箭只在成功转移时离开缓存；武器已装物资保存，发射不二次扣款 |
| A05 | 无限、创造模式、多重射击，与同版本无本模组基线比较 | 本模组不额外收费、不按弹丸数量错误扣料、不改变基线效果 |
| A06 | 原料消耗或装填过程中卸下终端，随后收到旧客户端操作 | 服务端停用缓存访问，已提交与未提交转移守恒，不补偿或复制物资 |
| A07 | 两种 TaCZ 弹种共享基础物品但身份不同 | 若兼容例外获准，过滤、取料与输出均保留正确弹种；不去数据合并 |
| A08 | TaCZ 常规换弹、换弹中断、空弹匣、不同弹种混放 | 检查和提取看到相同真实来源；装填只取实际需要量，射出已装弹不再扣缓存 |
| A09 | TaCZ 原有背包直读、虚拟备弹或不消耗配置 | 只适配其既有语义，不通过改配置让测试通过，不把虚拟备弹视为缓存实物 |
| A10 | 未安装 TaCZ；已安装首版必需的 Curios；独立服务器无客户端界面类 | TaCZ 缺失不阻止核心启动；Curios 供应链坠遵守统一佩戴边界，服务端不加载客户端界面类。无 Curios 护甲入口不属首版 |

**通过条件：** 版本可复现、物品身份保真、服务端事务守恒、保留原操作规则，且不要求侵入式修改第三方配置／内容。未通过不能标成已支持；具体 API 选择和原型结果应追加记录，不改写本次“未执行”的历史。
