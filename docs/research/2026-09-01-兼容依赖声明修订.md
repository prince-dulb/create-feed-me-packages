# 兼容依赖声明修订

- **核实日期**：2026-09-01
- **适用版本**：`v0.1.0` T05 测试构建
- **用户决定**：真正的模组依赖只有 Create 与 Curios；JEI、纸飞机、运输蜂的依赖声明全部移除
- **结论**：已实现并通过自动门；尚未据此宣称三个兼容功能已经联调

## 问题与结论

旧 `neoforge.mods.toml` 把 JEI 写成 optional 依赖，并限制在 `[19.21.0.247,19.22)`。Optional 只表示“缺失时可以继续”，安装后仍会校验版本范围，因此较新的 JEI 会被本模组元数据拒绝。NeoForge 的模组文件规范明确将 `versionRange` 解释为 Maven Version Range；开区间 `[最低版本,)` 虽能放宽，但用户决定从根源上移除这些非真实依赖。[NeoForge 模组文件说明](https://docs.neoforged.net/docs/1.21.3/gettingstarted/modfiles/)

核实时，JEI 官方 Modrinth 项目给 Minecraft 1.21.1 / NeoForge 列出的最新条目为 `19.51.0.417`，发布时间 2026-08-30，明显超出旧上限。它现在只作为以后 T11 的测试基线，任务开始时须再次核实，不进入模组依赖元数据。[JEI 19.51.0.417](https://modrinth.com/mod/jei/version/w1zqfWJi)

## 实施

- 生成的 `neoforge.mods.toml` 只保留 Minecraft、NeoForge、Create、Curios 四项 required 依赖。
- 删除 JEI、`cmpackagecouriers`、`create_mobile_packages` 三个 optional 依赖块及其版本范围属性。
- 删除尚未被源码使用的 BlameJared Maven 仓库和两个 JEI `compileOnly` API。
- 新增资源契约测试，要求依赖块恰为四个、不得出现 `type="optional"` 或三个兼容模组 ID。
- 兼容功能仍按原路线图实施，但采用隔离模块和运行时存在性探测；测试版本不限制整合包加载。
