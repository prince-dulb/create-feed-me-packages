# T04 供应链坠与网络绑定验证

- **验证日期**：2026-08-31
- **目标版本**：`v0.1.0`
- **平台组合**：Minecraft 1.21.1、NeoForge 21.1.219、Create 6.0.10、Curios `9.5.1+1.21.1`
- **任务结论**：T04 完成；下一项为 T05 物流面板与五阶段交互

## 1. 本次实现范围

本次实现供应链坠的实例数据、Curios 有效佩戴枚举、Stock Link 绑定、逐件清绑／禁用、稳定排序、重复终端 ID 修复，以及本地缓存门和新请求网络门。个人缓存仍以玩家 Data Attachment 为唯一权威；终端只保存 `terminalId`、一个可空网络 UUID、禁用状态和修订号。

绑定没有开放客户端 UUID 参数。玩家手持供应链坠潜行使用真实 Stock Link 时，服务端从当前方块实体的物流行为读取网络 UUID，并复核区块、距离、原版交互许可和 Create 自身的 `mayInteract`。相同网络重绑成功但不增加修订号。

T05 尚未实现玩家可操作的背包左侧面板。本次只接通清绑／禁用的服务端 payload 处理和 T05 将使用的访问快照；其他缓存菜单意图仍明确返回 `FEATURE_NOT_READY`。

## 2. API Spike 结果

### SPK-TERM-01：Curios 枚举

在实际解析的 Curios `9.5.1+1.21.1` API／实现中确认：

- `CuriosApi.getCuriosInventory(LivingEntity)` 取得服务端饰品栏；
- `ICuriosItemHandler.getStacksHandler(String)` 与 `ICurioStacksHandler.getStacks()` 取得指定槽的实际物品；
- `ICuriosItemHandler.isSlotActive(String, int)` 排除失活槽；
- FMP 只枚举普通装备栏中的 `necklace` 和通用 `curio`，不枚举 cosmetic 栏、普通背包或其他槽；
- 稳定定位使用“槽类型＋槽索引”，最终快照再以终端 ID 收束排序；
- 玩家槽资源采用 `data/create_feed_me_packages/curios/entities/player.json`，并已在真实 GameTest Server 日志中观察到 `Loaded 1 curio entities`。

测试扩展槽使用当前的瞬时槽修饰符 API，没有继续调用 Curios 已弃用的 `growSlotType`／`grow`。

### SPK-TERM-02：Create Stock Link 网络读取

在 Create 6.0.10 实际 JAR 中确认：

- Stock Link 方块实体为 `PackagerLinkBlockEntity`；
- 物流行为位于 `stockLink.behaviour`，实际网络 UUID 为 `behaviour.freqId`；
- 绑定额外执行 `LogisticallyLinkedBehaviour.isValidLink` 与 `behaviour.mayInteract(player)`；
- 已加载网络的可见性使用 `LogisticallyLinkedBehaviour.getAllPresent(networkId, false)`，至少存在一个有效同 UUID 链接时为 `READY`，否则保留本地访问并返回 `NETWORK_UNAVAILABLE`；
- Stock Link 没有抢占本次物品使用入口，因此供应链坠的标准 `Item#useOn` 可以作为绑定入口；保护模组仍可在该标准交互之前取消事件。

这两项 Spike 均固定在发布基线版本上通过，没有引入客户端 UUID 文本框、反射或第三方源码副本。

## 3. 已验证行为

### 领域与协议

- 无坠子为 `INACTIVE / BLOCKED_NOT_WORN`；全部禁用为 `MANAGEMENT_ONLY / BLOCKED_DISABLED`；未绑定但启用为 `ACTIVE / BLOCKED_UNBOUND`。
- 同网多件和“同网＋未绑定”只检查一次网络；不同网络不选择任意一方，直接进入 `MANAGEMENT_ONLY / BLOCKED_CONFLICT`。
- 禁用冲突中的一件可恢复剩余网络；重新启用、Curios 槽失活／恢复会立即重算。
- 清绑与禁用以槽定位、终端 ID、终端修订号三重校验；旧修订或换槽后提交不会改另一件物品。
- 复制出的相同终端 ID 同时装备时，稳定排序后的后一件取得新 UUID，修订号加 1，网络和禁用状态保留。
- payload 只下发网络 UUID 的 8 位显示短 ID；客户端不能通过清绑／禁用载荷提交网络 UUID。

### 真实 NeoForge／Create／Curios 运行

- 新供应链坠的注册默认栈没有共享实例 UUID；服务端制作、物品 tick 或首次合法绑定时为具体栈初始化 UUID。
- 普通背包中的坠子会获得自己的组件，但不会激活缓存，也不会因为只读访问检查而创建玩家缓存。
- Curios `necklace` 中的坠子能启用本地访问；失活槽不参与归并。
- 对真实放置的 Create Stock Link 潜行使用供应链坠，读取到测试写入 `behaviour.freqId` 的真实 UUID；同网重绑不增加修订号。
- Stock Link 从 Create 活跃链接集合移除后，终端由 `READY` 变为 `NETWORK_UNAVAILABLE`，绑定值不被自动清除。
- 非供应链坠、错误方块和超距交互均被拒绝，且拒绝路径不会初始化或修改目标坠子。
- A 将已绑定坠子交给 B 后，绑定随物品保留；B 初始化和访问的是 B 自己的玩家附件，A 的缓存记录逐字段不变。

## 5. 验证边界与残余工作

- GameTest 使用真实 Curios capability、真实 Stock Link 方块实体和真实 Create 活跃网络集合，但不是两名真人客户端的游戏内操作录像。
- 普通客户端只验证启动与资源加载；T05 背包面板尚不存在，因此没有 UI 点击、冲突管理或复制地址的人工验收。
- `READY` 目前只表示终端绑定的 Create 网络在已加载链接集合中可见；T06 还要叠加库存查询、完整包提供者资格、请求承诺和退避。
- 同网多件“不重复发单”当前只证明归并后有唯一有效网络检查；真正一个缺口只发一次包必须在 T06 请求协调器完成后再验收。
- 尚未安装或联调纸飞机、运输蜂、JEI；也未执行两玩家专服、UI 40 组矩阵、性能与真实物流闭环。
- 启动日志中的 `ApiStatus$ScheduledForRemoval` 缺类警告来自 Curios 开发环境的可选注解类；本项目编译无弃用警告，客户端、专服和 GameTest 均继续完成。

据此，T04 的完成条件已有自动与运行证据；M1 的代码范围完成，但 M1 路线图要求的真人断线／重启／转交整体验收仍留到后续系统与多人矩阵，不把本次 GameTest 写成完整产品闭环。
