## 转移守恒回归覆盖（对应用户报告的"疑似刷物品"序列）

1. `t05StaleFullStackWithdrawAfterHalfTakeConserves`：取 32 后再以过期数量取 64——服务端按格内现货 32 与光标可容 32 封顶，光标终值恰为 64，格清空，总量 64 不变；
2. `t05WithdrawThenDepositBackConserves`：取 32 放回 32——光标清空、格恢复 64；
3. `t05CollectAfterSplitTakeConserves`：双击收集——先收背包匹配堆再收缓存，光标满 64 后继续收集被 `TARGET_FULL` 拒绝且总量不变；
4. `t05StaleRevisionRejectsAndConserves`：过期修订号拒绝，格、光标、背包全部不动。

结论：报告的操作序列在服务端不存在复制路径；感知上的"多出一组"与最低数量启用时的补货回填一致（详见变更说明"待复测说明"）。
