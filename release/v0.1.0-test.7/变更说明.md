# v0.1.0-test.7 变更说明

本构建修复 `test.6` 人工测试反馈的缺陷，并补守恒回归。核心行为规则（补货只看缓存、部分入库、残包续收、切点守恒）与 `test.6` 完全一致，没有放宽或收紧任何玩法边界。

## 修复 1：服务端状态变化现在即时推送快照（对应"手动放入损坏"与 UI 迟滞）

此前快照只在客户端每次点击的服务端响应里返回；服务端的补货派单、包裹收包和升级使用都会推进缓存修订号，但从不主动通知客户端。玩家在补货活跃的存档里点击面板时，携带的旧修订号被服务端按过期拒绝，点击看起来"没反应"。

现在三处服务端发起的修订变化都会向在线玩家推送权威快照：

- 补货请求提交（`RestockService`，待收记录写入后）；
- 专用包裹收包提交（`PackageReceiveService`，入库事务提交后）；
- 升级件使用成功（`CacheUpgradeItem`）。

意图驱动的操作仍走原响应快照，不重复推送。

## 修复 2：面板无快照时立即请求（对应"回到背包页 UI 迟到一秒"）

客户端快照轮询周期为 1 秒；从 Curios 饰品栏回到背包页或任何状态被清空的时机，面板要等满 1 秒才出现。现在无快照时以 150ms 的重试下限立即请求，拿到快照后恢复 1 秒周期。

## 新增守恒回归（GameTest 4 项，回应"疑似刷物品"）

针对报告的操作序列，在真实服务端函数上断言 光标 + 缓存现货 + 背包 内的物品总量恒等于事务前：

1. 取出一半后再以过期数量取整组——第二次被服务端按格内现货与光标容量封顶，光标恰为一组，无净增；
2. 取出一半再放回——光标与格内合并复原；
3. 取出一半后双击收集——先收背包匹配堆再收缓存，满光标后拒绝继续；
4. 过期修订号拒绝且不动任何物资。

四项全部通过，服务端不存在报告序列下的物品复制路径。
