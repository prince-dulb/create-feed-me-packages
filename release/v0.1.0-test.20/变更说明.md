# Create: Feed Me Packages! 0.1.0-test.20 — 变更说明

## 相对于 test.19 的变更

### 统一组容量模型（用户确认）

- **所有物品在同一等级共享相同的组数上限**：`groupCapacity = capacity / 64`（等级 1–5 分别为 2, 4, 8, 16, 32 组）。
- 单格物品容量 = `groupCapacity × item.stackSize()`。例如等级 1：橡木木板（64 堆叠）= 2×64=128；末影珍珠（16 堆叠）= 2×16=32；牛奶桶（1 堆叠）= 2×1=2。
- 域层 `CacheLevel.groupCapacity()`、`CacheState`/`CacheEdit`/`CacheMerge` 校验全部改用此公式。

### 显示回归物品数

- 滑条和标签显示精确物品数量（如 32、64、128），内部逻辑仍以组为单位。
- 不再显示「N 组」格式。

### Schema 5 + 迁移

- `CacheLedger.SCHEMA` 从 4 升至 5。
- 支持 schema 2→5 和 4→5 迁移：旧阈值÷stackSize 转组数，超出新 per-item 容量的数量/阈值截断。

### GameTest 修复（4→0 失败）

1. `inventoryInsertionHonorsNativeLimitsAndNoRoom`：升级缓存至等级 2，使鸡蛋容量=64 匹配 4×16 存入。
2. `cakeUsesThreeByThreeAndKeepsBucketsWithoutRestockOverwrite`：升级至等级 3（groupCapacity=8），牛奶桶容量=8 ≥ 6。
3. `manufacturingAuthorityAndLateParcelsSurviveAnotherJvm` / `currentModelPersistsInRealPlayerFilesAcrossJvm`：跨 JVM 探针接受可迁移的旧 schema（≥2 且 ≤SCHEMA），而非仅精确等于当前 SCHEMA。
4. 清除旧 GameTest 世界探针和 ledger 数据，使其以 schema 5 重新写入。

### 验证结果

- JUnit：16/16 通过
- GameTest：84/84 通过（含跨 JVM 持久化两轮验证）
