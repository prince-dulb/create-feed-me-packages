# test.14 变更

## 修复创造存取交接

此前从缓存取出到创造光标，再放进原版物品栏、关闭界面，会残留另一份服务端光标并被原版回收。现按创造界面的原生协议只交接一份；不是关闭时补扣物品，也没有禁用创造面板。

## 合成准备与实际消费分开

- 配方书／JEI准备原料时，材料仍在原背包或缓存中，合成格显示有来源的预留，不因此产生补货缺口。
- 取走产物才结算实际完成的合成；反复选择、取消、关闭和最后一轮尚未消费的准备不会多扣料。
- 手动从预留合成格拿走原料，会转成真实取出并扣相应来源。
- 预留量不能同时被面板、弹药或另一笔事务再次使用。源格变化、卸下、旧菜单及重复请求有服务端检查。
- 满背包、批量和桶余物检查计入未用原料，不将临时空位重复分配给产物。

真实工厂专项：首包64个原木，合成一次得到4块木板，只补发1个原木，缓存回到64。没有通过统计普通背包、清空请求或隐藏箭头掩盖多扣料。

## 小项修订

- 固定背包优先，不足由缓存补足；去掉切换按钮，旧偏好及旧切换请求也不生效。
- 扩容链节、框架、中间产物按步骤显示1—4号，对应1→2至4→5级；内部目标等级ID不变。
- 已绑定链坠显示附魔光效，但不添加实际附魔数据。
- 模组版本号由构建统一生成；元数据、Manifest与文件名一致。
