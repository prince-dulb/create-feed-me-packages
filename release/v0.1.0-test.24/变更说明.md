# Create: Feed Me Packages! 0.1.0-test.24 — 变更说明

## 相对于 test.23 的变更：私人定坠改为「物主锁定」

用户反馈：私人定坠无法升级，且同一玩家连续升级被「佩戴签收容量授权」机制阻拦；这一机制本意是防止物品在玩家间流转一圈就让全服都开满级，却误伤了本该顺畅升级的物主。

按用户三点定稿重构为「物主锁定」：

### 1. 物主固定为锻造者
- 私人化（普通坠→私人坠）时，成品坠子写入 `OWNER = 锻造者 UUID` 与物主名，永久归属该玩家。
- 私人化时普通坠整份内容转入**锻造者**的个人缓存（放不下则整体拒绝，不消耗输入）。
- 同一物主锻造出的所有私人定坠共享**同一个**个人缓存，等级随之共享。

### 2. 只有物主可访问/升级
- 仅物主佩戴时访问其个人缓存。
- 物主可在锻造台用对应链节「直接」升一级物主个人缓存，不再有「待签收授权/佩戴签收」，因此同一物主可连续升到 5 级。
- 非物主（或旧的无物主坠子）在锻造台锻造升级会被拒绝（`not_owner`）。

### 3. 非物主佩戴即退化为普通版
- 其他玩家佩戴不属于自己的私人定坠时，坠子立刻**退化成全新的普通供应链坠**（换成带新本件缓存的普通坠），无法访问物主私人缓存；物主缓存与其余钥匙不受影响。

### 4. 移除授权流水
- 删除 `CAPACITY_GRANT` 组件、`grants` 表、`prepareGrant`/`prepareClaim`/`ledger.pending`/`GrowthService.claimPending`。
- 物主显示在物品描述（如「名匠：某某」），替代原来的授权行。
- `SCHEMA 7`（去掉 grants 字段；旧 schema 6 世界仍可读取迁移，旧授权视为废弃忽略）。

### 测试基建
- 运行 profile 后缀改 `-model8`（schema 变更后重开新世界；旧 `-model7` 保留未删）。
- 重写授权相关 GameTest：`personalUpgradeBelongsToOwnerAndAdvancesItsCache`、`personalPendantIsOwnerLockedAndDegradesForOthers`、`firstPersonalizationThenOwnerUpgradesStayOrdered`、`ownerLockedPersonalManufacturingSurvivesAnotherJvm`。

## 请复测

1. 私人定坠现在能连续升级：物主锻造一次升一级，最高可到 5 级，不再被「还有未签收授权」阻拦。
2. 私人定坠 tooltip 显示「名匠：<玩家名>」。
3. 把私人定坠交给另一名玩家佩戴，它会立刻变成一枚新的普通供应链坠；物主的私人缓存不受影响。
4. 同一物主多枚私人定坠共享同一个私人缓存与等级。
