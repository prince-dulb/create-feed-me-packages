# v0.1.0-test.9 变更说明

本构建按方式 2 一次性交付 T10／T11／T12 三块功能，完成 v0.1.0 的全部功能开发。核心缓存与收发逻辑与 `test.8` 完全一致。

## T10：原版配方书取料

在原版背包 2×2 与工作台 3×3 中，点击配方书（或 JEI 转移，见 T11）时，系统把**背包与缓存中的真实材料**按来源优先级放进合成格：

- 先转移后合成：材料是真实 `ItemStack`，结果、余物、消耗全部由原版处理。
- 离开缓存即扣：缓存材料进入网格的瞬间扣减并触发补货检查。
- 背包优先／缓存优先双模式，首选不足自动用另一来源补足；两来源合计不足则整体失败、什么都不动。
- 网格里已放对的材料优先保留；放不下旧材料的清格整体拒绝（`GRID_CLEAR_BLOCKED`），不掉落不吞物。
- `MAX` 填充受格内原生堆叠上限约束；同一格不混两种物品。
- 只用本地现货：待收与 Create 远端库存不算可用量。
- 实现入口为原版配方放置的单点 Mixin（`RecipeBookMenu.handlePlacement`）：未佩戴、全部禁用或异网冲突时完全交还原版行为，原版本可用的配方不受影响。

## T11：JEI 过滤与配方转移（可选，装 JEI 自动启用）

- JEI 拖物品到物流格 → 设过滤（不影响来源实物）。
- JEI 配方转移按钮 → 发送与配方书相同的服务端意图，服务端重算，客户端只提交候选偏好与模式。
- JEI 未安装时兼容模块不加载；不覆盖熔炉、机器或第三方菜单。

## T12：弓弩弹药取用

- 原版弓、弩及一切走共享投射物查询链的武器（含第三方子类）在背包无箭时，从缓存取出 1 支合法弹药。
- 扣减发生在拉弓查询瞬间，与原版"拉弓即消耗"一致；背包有箭时优先用背包，缓存不动。
- 无吊坠、缓存无合法弹药时完全原版行为；不修改射击、附魔（无限／多重按原版计数）与任何枪械配置。

## 新增守恒与安全测试（GameTest 13 项，总计 61/61）

T10 八项：缓存独供＋原版结果、来源优先序（双模式对照）、缺料全不动、MAX 堆叠上限、nonce 重放、旧修订拒绝、未佩戴交还原版、3×3 配方进 2×2 拒绝。T12 五项：弓从缓存取箭、背包优先、自定义走链验证（十字弓代证，未注册子类因注册表冻结无法运行时构造，移交真实模组联调）、不支持物品忽略、卸坠后缓存不可见。另有 `t05` 敌意载荷测试：`Integer.MAX_VALUE`／负数计数经真实意图入口封顶或拒绝。

## 已知边界

- 配方书取料不支持修理类等无法安全表达的动态配方（明确报"无法安全自动填充"）。
- 多重射击附魔下缓存一次只供 1 支箭（与背包仅剩 1 支的行为一致）；无限附魔正常免耗。
- JEI 界面内的实际交互（拖入、转移点击）需游戏内人工验证。
