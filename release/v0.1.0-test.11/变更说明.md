# v0.1.0-test.11 变更说明

本构建是对 `test.10` 首轮人工测试（2026-09-05 报告七项）的响应。核心身份/迁移逻辑与 `test.10` 一致，无数据格式变化。

## 已修（本构建）

1. **创造模式界面与生存模式对齐**（反馈第 6 项）：删除创造物品栏的全部特殊分支——手持物品放入物流格、`Shift+点击` 存入在创造与生存下走完全相同的入口，由服务端统一校验，不再有"创造只设过滤"的特殊化。
2. **JEI 编译基线降至 `19.21.0.246`**（反馈第 7 项相关）：`19.44+` 的 JEI 要求 NeoForge `21.1.238+`，与本项目的 `21.1.219` 不兼容；新基线是能在 219 上加载的版本，兼容模块对两个基线都能编译。另在开发实例中加入完整 JEI（仅本地 `runClient` 验证用，绝不进入发布依赖）。
3. **新增"地址不符包裹"诊断日志**（反馈第 3 项定位用）：背包里的 Create 包裹若地址不是本玩家的 `FMP@名字`，客户端日志会以 5 秒冷却记录"ignoring a package addressed to '…' (expected '…')"，用于定位包裹为何未被自动拆包。

## 诊断结论（待用户补充证据）

- **第 3 项（包裹不自动拆包）**：真实 Create 链路的端到端已由新增 GameTest `t06RealDeliveredPackageAutoUnpacksIntoCache` 本地复现并通过（打包机出真实包裹 → 放入背包 → 自动拆入缓存 → 待收清零）。本地无法复现"不拆包"，最可能的原因是包裹在你世界里的地址不是 `FMP@你的名字`（运输环节改写/未写地址）。**请提供该次测试的 `logs/latest.log`**，新诊断会直接写出被忽略包裹的实际地址。
- **第 4 项（手拆后箭头还在）**：现行为符合规格——箭头表示"本格有未完成的待收记账"，手动拆包不经过本模组、不清记账（规格明确不判断包裹丢失）；可用滑条里的"重置本格待收"清除。第 3 项修好后此场景应消失；若希望"手拆包裹自动清待收"属于规格修订，请与主策划确认。
- **第 2 项（悬停圆石时 tooltip 错位/"64"悬空）**：tooltip 文本构造正确（应为"待收 64"与"空库存格：…"），截图中前两个字符不可见的成因尚未复现。已排除文本缺行；请附带说明是否使用了字体/界面类资源包，下轮在真实环境复测。
