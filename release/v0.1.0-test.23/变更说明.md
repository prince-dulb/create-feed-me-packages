# Create: Feed Me Packages! 0.1.0-test.23 — 变更说明

## 相对于 test.22 的变更

### 1. 残包按物品格分格（模型改动）

用户反馈：A 物品有未进入库存的包裹（残包）时，B 物品的包裹到货后会先进背包，等 A 的残包被吸收后 B 才进入「待解包」状态——因为旧实现是**每份缓存只有一个残包位**，不同物品的残包互相抢占。

改动：残包改为按**精确物品变体**分格存储，每个物品格独立持有自己的一个残包位，互不阻塞。

- `CacheRecord`：`ItemStack residual` → `Map<ItemVariantKey, ItemStack> residuals`（按目标变体键）；新增 `residual(variant)`、`anyResidual()`、`withResidual(variant, box)`。
- `ReceiveService`：收到某物品包裹时，仅当其目标格已有残包才拒收；不同格的残包可同时存在；续收时逐格独立 resume。
- `PanelNetwork` / `LogisticsPanel`：残包绿点按格判定，多格可同时显示。
- `PrivateCacheMerge`：私人化合并时逐变体合并残包；若同一变体两边都各有残包则整体拒绝。
- `CacheLedger`：`SCHEMA=6`，残包按「变体 + 包裹」写入；支持 schema 2/4/5→6 迁移。
- 面板残包提示精简为「余货待解包」。

### 2. 成长链与面板提示精简

用户反馈：私人化二级坠子后连续升级，遇到「不允直接操作」时冒出一大堆长句，违反低信息压力。

改动：把 `message.create_feed_me_packages.growth.*` 全部精简为一句短话（如 `wrong_level` 从「链节等级不符：每次只能从当前等级提升一级。」改为「等级不符，只能升一级」）；同时精简面板的 `empty`/`slot_help`/`pending`/`requested`/`shortage`/`minimum_help`/`number_range`/`residual` 等悬停提示。仅改文案，不改行为。

### 3. 测试基建

- 运行 profile 后缀 `-model2` → `-model7`（schema 变更后重开新世界；保留旧目录未删）。
- 新增 GameTest `perCellResidualsDoNotContend`。

## 请复测

1. 设置物品 A、B 两格各设过滤，A 有一个未解包残包；随后 B 的包裹到货，B 应立即进入「待解包」（残包绿点），而不是先落回背包、等 A 吸收后才轮到自己。
2. 吸收 A 的残包后，B 的残包状态不受影响。
3. 升级链的提示文字应更短、更一目了然。
