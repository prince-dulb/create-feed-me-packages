# v0.1.0-test.17 变更说明

本构建由长期执行者接手后续开发的第一轮：基线为组长参考实现 test.16（已移植进根工程），实现 2026-09-06 用户确认的三项优化。核心收件、制造、私人化逻辑与 test.16 一致，但**阈值/容量计数单位变更并升级 schema 3**。

## 三项用户优化

1. **计数逻辑从"个"改为"组"**（反馈 1）：
   - 物流格容量与最低阈值以**组**为单位：1 级单格 = 128 组。实际可容纳的物品数量随物品堆叠上限变化——64 堆叠物品（石头）单格可存 8192 个，16 堆叠物品（末影珍珠）可存 2048 个，不再"同格同上限"。
   - 滑条、数字输入、滚轮的数值全部按组计（滚轮步进 1 组，Shift 16 组，Ctrl 64 组），"不足时补回最低数量"的补货差额仍按真实物品精确计算。
   - 实现：域模型引入 `MaterialVariant.stackSize()`（`ItemVariantKey` 在构造时从实物捕获堆叠上限），容量校验、插入容量、合并校验全部乘以组尺寸；内部库存仍按真实物品守恒。
   - **schema 2 → 3**：阈值字段语义变化，按参考轨"不为测试世界做迁移"的既定边界直接升版；旧测试世界载入会被拒绝并整记录保留（新开存档即可），不静默改数值。
2. **滑条改为覆盖层**（反馈 2）：双端滑条不再把下方格子挤走、不再撑高面板；打开时浮在格子之上（渲染层级高于物品图标），面板几何与未选中时完全一致；滑出屏幕底部时自动钳制。
3. **余包提示改为逐格绿点**（反馈 3）：移除旧左上角黄色脉冲块；改为**每个格子的左下角**一个 3×3 绿色小点，点亮表示该格物品在残包中还有余货；悬停格位给出提示。服务端在面板快照里按残包内容物匹配格位（`CellView` 新增 residual 位）。
