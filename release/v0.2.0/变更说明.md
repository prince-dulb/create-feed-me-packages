# Create: Feed Me Packages! v0.2.0 — 变更说明

## 相对于 v0.1.1（test.25 代码）的变更

v0.2.0 以 `fe42c7e`（test.58 合并版）为基础。主要变化按玩家可见功能列出。

### 自动退货

- 每个缓存可设一个**默认退货地址**（面板底部地址栏，点击输入、回车保存、Esc 取消）。
- 某一格的现货超过你设的**最高值**时，超出部分自动按合法包裹容量打包装箱，发往该退货地址。
- 载体为**纸飞机零件**（Package Couriers）或**运输蜂**（Create: Mobile Packages）：先尝试纸飞机，被拒后再尝试运输蜂；两者都不存在时**不打包、不扣物、不消耗**。
- 只有载体**真实受理**后才扣缓存与载体（同一次事务）；发运失败保持原状，留待下次。
- 面板该格显示退货箭头：**真实发运成功且仍超额为红色**，无成功依据或失败为**灰色**，退到最高值后消失；状态不持久化，换缓存／网络／地址／过滤／最高值不会沿用旧结果。

### 取物预留（拿起不等于已拿走）

- 从缓存格取出时，物品先以**预览**形式出现在光标上：缓存数量不变、不触发补货。
- 真正放进背包／合成格／地面后，服务端才**真实扣减**缓存。
- 放回原格：**净零**（不重复计入）；关闭界面或卸下饰品时，**未落位的预览被取消并留在缓存**，已放下的部分不回滚。
- 自动取料（配方书／JEI／弓弩弹药）与退货共用同一份可用量口径，不会重复占用同一批物资。

### 容量按“组”统一

- 1—5 级单格容量统一为 **2／4／8／16／32 组**；每组的物品数按该物品自身堆叠上限换算（64 堆叠的物品在 1 级为 128 个，16 堆叠的为 32 个）。
- 滑条以“组”为最小刻度，双端点分别设**最低值**（补货）与**最高值**（退货）；拖到最右为“不退货”。

### 满背包收件口

- 背包与快捷栏全满时，专用投递包裹仍能通过本模组的收件口直接进入缓存，不必先腾位。
- 装不下的部分保留为**残包**：每个物品格各有自己的残包位（面板左下角绿点提示），有空间时自动续收，容量有限、不会变成无限仓库。

### 面板与交互

- 面板改为紧凑布局（横向按等级扩展），地址横幅点击复制，滑条覆盖在格子上方不再挤走格子。
- 修复：创造模式存取复制、物品图标错位、面板与 tooltip 层级、滑条端点超出轨道 1px、按住端点不动却改数值等。

### 数据格式

- 缓存 schema 升到 **8**（每缓存默认退货地址）。精确组件身份（物品 ID＋完整持久化组件）语义不变。
- 面板网络协议标识升到 **4**；同一存档请让客户端与服务端使用同一份 0.2.0，不要混装旧客户端与新服务端。

### 仍不在本版

- 插件构筑（v0.3.0 计划）、纸飞机／运输蜂的主动退货运输格、TaCZ 弹药消费适配、第三方背包入口。
