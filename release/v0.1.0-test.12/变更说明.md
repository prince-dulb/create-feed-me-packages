# v0.1.0-test.12 变更说明

本构建基于你提供的 `logs/latest.log` 定位并修复了两个根因（收包失败与 JEI 失效），并修复 UI 层级与创造模式残留问题。数据格式无变化。

## 根因修复

1. **收包失败（上轮第 3 项）——已定位并修复**。日志显示每次收包都在 `digestOfRecord` 抛 `Can't access registry minecraft:enchantment`：你的缓存里有一本**附魔书变体**，而收包日志摘要用了裸 NBT 编码，遇到需要注册表的组件（附魔）就失败，导致**任何包裹都无法自动拆包**（每 20 tick 重试、每秒刷一条错误）。已改为注册表感知编码，并新增回归测试"缓存中存在附魔书变体时收包"。
2. **JEI 拖拽无反应（第 7 项）——已定位并修复**。日志显示 JEI 19.51 **明确禁止**为背包界面注册幽灵拖拽（"it would interfere with using JEI"），我们的注册在启动时即被 JEI 拒绝，整个界面处理器（含工作台 ghost）都没生效。处理：
   - 移除被禁止的背包界面注册（工作台界面的 ghost 保留）；
   - 按你的建议实现**中键过滤选择模式**（替代品）：游戏中键点击任意位置开启/关闭"选择过滤"模式；开启后**按住 JEI 列表里的物品拖到物流格上松开**即设为该格过滤（不需要背包里有实物）；Esc 退出。这正好也覆盖"背包没货时自选需求物品"的诉求。
3. **UI 层级问题（第 2 项）——已修复**。两处：
   - 物流格的物品图标渲染在较高层级，会**穿透**后绘制的双端滑条面板（截图里附魔书图标压在滑条上即此因）；滑条面板已整体抬升到物品图标之上。
   - 设置面板打开时，格位悬浮提示仍在面板下层渲染造成文字混层（此前截图里悬空的"64"、缺字即两层面叠印）；现在设置面板打开期间不再发格位悬浮提示。

## 其他修复

4. **创造模式手持物品点空格报"来源物品已不存在"**：创造标签页里的物品是幽灵堆栈，服务端没有实体可扣。现在按标签页区分——**生存标签页**内与生存模式完全一致（真实存取）；**创造标签页**内放置/点击只设过滤（等价 ghost）。另将判定所需标签页访问经客户端 Mixin 实现（客户端专属配置，公共类扫描保持干净）。
5. JEI 兼容基线回到 `19.51.0.418`（与你环境中的 19.51.0.417 同代）；开发实例另行使用能在 NeoForge 219 上加载的 19.21.0.246 做本地验证。上轮对 19.21 基线的判断对你的环境不适用（你的 NeoForge 是 21.1.249，JEI 19.44+ 可正常加载），已纠正。
